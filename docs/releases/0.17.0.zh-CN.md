OpenWalkieTalkie 0.17.0 修好了 Windows 上的听写。在 Windows 预览版上，按下 PTT 说话不会得到任何文字：识别还没完成就超时了。现在大约一秒就能完成。

对讲机固件没有变化，仍是 0.14.0。macOS 和 Omarchy 上没有变化。

## 问题出在哪里

在 Windows 上，Whisper 在 CPU 上运行。有两个原因让它在那里慢得多：

- **whisper.cpp 编译时没有开优化。** 使用 Visual Studio 生成器时，`cmake` crate 会用不带 `/O2` 的参数覆盖 `CMAKE_C_FLAGS_RELEASE` 和 `CMAKE_CXX_FLAGS_RELEASE`，所以 Windows 预览版的发布构建里带的 whisper.cpp 是用 `<Optimization></Optimization>` 编译的，完全没有优化。
- **Windows 用的是 Mac 的解码设置。** Linux 早就告诉 Whisper 它 30 秒的窗口里有多少是音频，并且只解码一遍，不再用更高的温度重试。Windows 沿用了适合 Metal 的 Mac 默认值：按 2 秒，编码器也要跑完整个 30 秒窗口，失败的一遍还要重新解码。

两者叠加，一次很短的按键也可能超过一次听写的 30 秒时限，这时完全得不到文字。

## 改了什么

- 发布流程的 Windows 构建把 `CMAKE_C_FLAGS_RELEASE` 和 `CMAKE_CXX_FLAGS_RELEASE` 设为 `-O2 -Ob2 -DNDEBUG`，whisper.cpp 会以优化方式编译。
- 在 Windows 上，和 Linux 一样，Whisper 只解码一遍，只编码这次按键需要的那部分窗口。
- 模型加载时，服务日志会记录 whisper.cpp 编译时启用的 CPU 特性（`whisper stt: system info`）。每次解码的耗时、音频长度、编码窗口和线程数记录在 debug 级别（`whisper stt: decode`），从不记录说的内容。

## 如何验证

在一台 Beelink EQ 迷你主机上（Intel Core i5-13420H，8 核 12 线程，31.8 GB 内存），使用 `ggml-small.bin` 模型，`language = "zh"`，对讲机通过 USB 连接，对三个构建说同一句话：「收到，已经下发了。」

| 构建 | 结果 |
| --- | --- |
| 发布的 0.16.0（whisper.cpp 未优化，Mac 的解码设置） | 没有文字。两次按键，分别用 `small` 和 `large-v3-turbo-q5_0`，都以 `stt: final decode failed; nothing sent error=speech recognition timed out after 30000 ms` 结束 |
| 用 Linux 的解码设置，whisper.cpp 仍未优化 | 17,242 毫秒后出字（`stt: final decode completed decode_ms=17242`）；两次解码分别用了 8,867 毫秒（1.1 秒音频，`ok=false`）和 9,987 毫秒（2.5 秒音频，`ok=true`） |
| 0.17.0（两项修复） | 1,124 毫秒（`stt: final decode completed decode_ms=1124`）；解码 2.2 秒音频用了 1,115 毫秒（`audio_ctx=512 threads=8 ok=true`） |

这比同一颗 CPU 上的参考实现 `whisper-cli` 1.8.3 还快：它处理一段 3.9 秒的音频用了 1.7 到 1.9 秒。

0.17.0 的识别结果是 `收到已经下发了`：七个字全部正确，顺序正确，是简体字。逗号和句号都没有输出。

## 自己在 Windows 上构建

本地的 Windows 构建也必须设置这两个变量，否则 whisper.cpp 又会在没有优化的情况下编译：在上面的测试里，一次解码要多用大约九倍的时间。在 PowerShell 中：

```powershell
$env:CMAKE_C_FLAGS_RELEASE = "/O2 /Ob2 /DNDEBUG"
$env:CMAKE_CXX_FLAGS_RELEASE = "/O2 /Ob2 /DNDEBUG"
cargo build --manifest-path host/Cargo.toml -p deckd -p openwalkietalkie-app --release --locked --target x86_64-pc-windows-msvc
```

在 Git Bash 中要写成短横线形式（`-O2 -Ob2 -DNDEBUG`）：Git Bash 会把以斜杠开头的值改写成路径。在 cargo 配置的 `[target.'cfg(windows)'.env]` 里设置是无效的（cargo 会忽略它），改用 `_CL_` 则会破坏 CMake 的编译器检测。日志里的 `whisper stt: system info` 一行会显示这次构建启用了哪些 CPU 特性。

## 更新

在 Windows 上，从发布页下载 ZIP。在 Mac 上选择 **检查更新…**，或者安装已签名、已公证的 **0.17.0** 应用（Apple 芯片或 Intel，macOS 13 及以上）。在 Omarchy 上，拉取代码，构建服务和应用，再用这两个文件运行 `install.sh`，步骤见 [Omarchy 指南](https://openwalkietalkie.org/docs/omarchy/)。这个版本不需要更新对讲机固件。
