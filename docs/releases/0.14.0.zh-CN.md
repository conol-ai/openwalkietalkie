OpenWalkieTalkie 0.14.0 是迄今为止最大的一次更新：

- Mac 应用变成设备的伴侣应用；
- 服务也能在 Windows 和 Omarchy（Linux）上运行；
- Grok Bot 与 Claude Code、Codex 一起出现在设备上；
- 固件安装改为在设备上确认。

## Mac 应用成为设备的伴侣

会话在设备上查看和回复，会话内容不会出现在应用窗口里。窗口只管理设备和它背后的服务，共五个页面：

- **设备（Deck）**：设备当前显示的页面，以及连接、电量、固件和设备设置。
- **页面与按键（Faces & Keys）**：设备的各个页面和宏键盘（Macropad）的按键。
- **集成（Integrations）**：哪些来源把会话送到设备上、它们是否正常送达，并提供 **Send a Test Question**（发送测试提问），以及每个集成的 **Set Up** / **Repair**。
- **语音（Voice）**：语音识别和语音回复，提供 **Test Voice** 和 **Speak a Sample**。
- **服务（Service）**：
  - **Check my setup**；
  - **Export Support File**；
  - 更新；
  - 已安装内容一览，以及 **Uninstall**。

首次运行时，在你选择 **Add These** 之前不会安装任何东西。

会话列表、卡片回复、指令输入框和用量页面已从窗口中移除，它们都在设备上。在设备上对会话卡片按 ENTER，会把该会话所在的应用切到前台（**Open app**），不再需要“自动化”权限。设置按设备分别保存。服务会自行检查更新；设备断开 10 分钟后停止收集数据。云端语音密钥保存在钥匙串中。窗口支持“增强对比度”，也可以只用键盘和菜单操作。

## 设备上的 Grok Bot

Grok Bot（xAI 的协作应用）是新加入的集成，与 Claude Code、Codex 并列：

- **从设备到机器人。** 每个机器人是设备上 **Grok Bot** 页面中的一行，显示 Grok 图标。对机器人按住说话，内容会发送到该机器人一个例行任务的 Webhook。
- **从机器人到设备。** 机器人在你的电脑上运行 `deckd grokbot say` 来回复：回答的简短版本显示在设备上并朗读出来，完整回答保留在机器人的聊天里。`deckd grokbot ask` 会在设备上显示一张提问卡片，并返回你的选择。

在 Mac 上设置机器人：打开 **集成 → Grok Bot → Bots…**。

1. 输入机器人的名称。
2. 选择 **复制提示词（Copy Prompt）**，把它发给 Grok Bot 聊天里的这个机器人。机器人会自己创建一个由 Webhook 触发的例行任务。
3. 把例行任务的 **POST 到** 地址和 **密钥** 复制到对话框中。
4. 在 Grok Bot 的 **设置 → 电脑** 中，允许机器人运行命令。

密钥在 Mac 上保存在钥匙串中，在 Windows 上保存在凭据管理器中。机器人运行的命令可以向设备汇报，但不能回答其他会话的卡片，也不能更改设置。在 Omarchy 上，用 `deckd grokbot prompt` 和 `deckd grokbot add` 完成设置。

## Windows（预览版）

服务和伴侣应用可以在 Windows 10 和 11（x64）上运行。每次发布都会附带未签名的 `OpenWalkieTalkie-0.14.0-windows-x86_64.zip`，旁边附有 `.sha256` 校验文件。

Windows 上支持：

- System 页面、Claude Code、Claude Channels 和 Codex；
- 宏键盘（⌘ 映射为 Ctrl）；
- 语音和 Grok Bot；
- 用凭据管理器保存密钥；
- 托盘图标、登录时启动以及应用内更新。

MLX 语音和 Codex Desktop 启动器仍只在 Mac 上提供。

由于没有签名，SmartScreen 需要选择 **更多信息 → 仍要运行**，“智能应用控制”会阻止运行。请按照 [Windows 安装指南](https://openwalkietalkie.org/docs/windows/) 操作。

## Linux：Omarchy

在 Omarchy（Hyprland）电脑上，Linux 版服务和 Omarchy 适配器会把这台电脑上的会话送到设备上。Omarchy 页面可以切换窗口和工作区，语音指令会输入到会话所在的终端：

- **会话：** Claude Code、Codex 和 Kimi Code 会话会出现在会话列表中。
- **语音：** 安装了 Superwhisper 时，由它识别按住说话的内容；服务自带的识别器作为后备。
- **宏键盘：** 按键通过 uinput 输入，因此 Omarchy 的 Super 快捷键可以生效。

Omarchy 上没有应用窗口，Linux 上也没有祖先进程上限。请按照 [Omarchy 指南](https://openwalkietalkie.org/docs/omarchy/) 构建和安装。

## 固件 0.14.0

- **在设备上确认安装。** 从固件 0.14.0 起，只有在设备上按 ENTER 才会开始更新；CANCEL、60 秒超时、语音和 API 都不会安装。从 0.13 升级到 0.14 这一次仍在应用中确认；处于恢复模式的设备会立即安装。
- **提问通知会接住下一次 ENTER。** 如果提问到来时设备没有在使用，下一次 ENTER 会打开提问卡片，再按一次即回答。跳转到新提问时，也不再打断正在运行的计时器、正在响的闹钟和游戏。
- **Grok 图标。** 设备会显示 Grok Bot 的图标，并告诉服务它能显示哪些代理图标，因此旧设备会改为显示通用图标。

## 需要注意的变化

- **祖先进程上限现在能识别原生安装的 Claude Code。** 这项保护会限制由代理启动的进程。以前，原生安装的 Claude Code 启动的进程不受这项限制，可以向服务申请管理员权限；现在不再可以。在 Claude Code 或 Codex 里运行的管理类 `deckd` 命令会被拒绝，请在你自己的终端里运行。hook 和 Claude Channels 不受影响。
- **本地 TCP 接口默认关闭。** 在仍可能有旧的 `http` 类型 Claude hook 使用它时，它会保持开启；下一个版本将移除它。
- **设备用量页面上的 Claude 用量改为需要手动开启。**
- **不再使用 Mac 麦克风录音。** 设备麦克风不可用时，服务不再退回使用 Mac 的麦克风。
- **钥匙串对话框不再反复出现。** 读取 Claude 用量时反复弹出的钥匙串对话框应当不再出现。

## 修复

- 设备可能朗读上一轮的回答。
- 无法送达的指令现在会在设备上显示为 **Not delivered**（未送达）或 **Unconfirmed**（未确认）。
- Kokoro 语音下载失败。
- 过期的 Claude channel 辅助进程会无限重试。

## 更新方法

- **Mac：** 选择 **Check for Updates…**，或安装适用于 Apple Silicon / Intel 的已签名并经过 Apple 公证的 **0.14.0** 应用；需要 macOS 13 或更高版本。如果服务仍显示旧版本，请打开 **服务** 并选择 **Restart**。
- **设备：** 用 USB 连接设备后，打开 **服务 → Updates**，选择设备旁边的 **Check**，然后选择 **Review…** 和 **Install**。这一次更新在应用中确认，之后的更新都在设备上确认。常规更新会保留设置及蓝牙配对；工厂镜像用于生产，会覆盖这些内容。
- **Windows：** 从本次发布下载 ZIP，并按照 Windows 安装指南操作。
- **Omarchy：** 用本次发布的源代码构建，并按照 Omarchy 指南操作。

## 验证

- **自动化测试：** 每项改动都运行了 macOS、Linux 和 Windows 的主机测试，以及 LilyGo、Rev A、Rev B 的固件测试。
- **实际硬件：**
  - Omarchy 搭配通过蓝牙连接的 Rev B：Superwhisper 识别、语音回复和 uinput 快捷键。
  - Windows 11：通过 USB 安装固件，以及通过设备扬声器播放语音。
  - Mac 搭配 Rev B：对 Grok Bot 按住说话并收到回复。
