OpenWalkieTalkie 0.14.0 is the largest release so far:
- the Mac app becomes the deck's companion;
- the service also runs on Windows and on Omarchy (Linux);
- Grok Bot joins Claude Code and Codex on the deck;
- the deck itself confirms its firmware installs.

## The Mac app is the deck's companion

You read and answer sessions on the deck, and no session text reaches the app's window. The window is for the deck and the service around it, on five pages:

- **Deck**: the deck showing its current face, with its link, battery, firmware and settings.
- **Faces & Keys**: the deck's faces and the Macropad's keys.
- **Integrations**: what puts sessions on the deck and whether each one is arriving, with **Send a Test Question** and **Set Up** / **Repair** for each integration.
- **Voice**: recognition and spoken replies, with **Test Voice** and **Speak a Sample**.
- **Service**:
  - **Check my setup**;
  - **Export Support File**;
  - the updates;
  - the footprint of everything installed, with **Uninstall**.

On first run, nothing is installed until you choose **Add These**.

The roster, card answers, the order box and the Usage page left the window; the deck has them. ENTER on a session's card now brings the session's own app forward (**Open app**), with no Automation permission needed. Settings are kept per deck. The service checks for updates itself, and stops collecting 10 minutes after the deck unlinks. The cloud voice key is kept in the Keychain. The window follows Increase Contrast and works from the keyboard and menus.

## Grok Bot on the deck

Grok Bot, xAI's teammate app, is a new integration, beside Claude Code and Codex:
- **Deck to bot.** Each bot is a row on a **Grok Bot** roster page, drawn with the Grok mark. A press on a bot goes to the webhook of a routine in that bot.
- **Bot to deck.** The bot answers by running `deckd grokbot say` on your computer: a short version of its answer appears on the deck and is read out, and the whole answer stays in the bot's chat. `deckd grokbot ask` puts a question card on the deck and returns your choice.

To set a bot up on a Mac, open **Integrations → Grok Bot → Bots…**:
1. Type the bot's name.
2. Choose **Copy Prompt** and send the prompt to the bot in Grok Bot's chat. The bot makes its own routine with a webhook trigger.
3. Copy the routine's **POST to** URL and **key** into the dialog.
4. Allow the bot to run commands in Grok Bot's **Settings → Computer**.

Keys are kept in the Keychain on a Mac and in Credential Manager on Windows. A command a bot runs can report to the deck, but it cannot answer another session's card or change a setting. On Omarchy, `deckd grokbot prompt` and `deckd grokbot add` do the setup.

## Windows (preview)

The service and the companion app run on Windows 10 and 11 (x64). Each release now includes an unsigned `OpenWalkieTalkie-0.14.0-windows-x86_64.zip`, with a `.sha256` beside it.

Windows has:
- the System face, Claude Code, Claude Channels and Codex;
- the Macropad, with ⌘ sent as Ctrl;
- voice, and Grok Bot;
- Credential Manager for keys;
- the tray icon, start at sign-in, and in-app updates.

The MLX voice and the Codex Desktop launcher stay Mac-only.

The build is not signed, so SmartScreen asks for **More info → Run anyway**, and Smart App Control blocks it. Follow the [Windows install guide](https://openwalkietalkie.org/docs/windows/).

## Linux: Omarchy

On an Omarchy (Hyprland) machine, the Linux service and the Omarchy bridge put that machine's sessions on the deck. The Omarchy face switches windows and workspaces, and voice orders are typed into the session's terminal:
- **Sessions:** Claude Code, Codex and Kimi Code sessions appear on the roster.
- **Voice:** Superwhisper, when installed, transcribes your presses. The service's own recogniser is the fallback.
- **Macropad:** keys type through uinput, so Omarchy's Super shortcuts work.

Omarchy has no app window, and Linux has no ancestry cap. Follow the [Omarchy guide](https://openwalkietalkie.org/docs/omarchy/) to build and install it.

## Firmware 0.14.0

- **Installs are confirmed on the deck.** From firmware 0.14.0 on, an update starts only when you press ENTER on the deck. CANCEL, the 60-second timeout, voice and the API install nothing. The update from 0.13 to 0.14 is still confirmed in the app, and a deck in recovery mode installs at once.
- **A question's toast takes the next ENTER.** If nothing was in use when a question arrived, the next ENTER opens its card, and the one after that answers it. Jumping to a new question now also leaves a running Timer, a ringing alarm and a game alone.
- **The Grok mark.** The deck draws Grok Bot's mark, and it tells the service which agent marks it can draw, so an older deck shows a generic mark instead.

## Changes to know about

- **The ancestry cap now sees a natively installed Claude Code.** The safeguard limits processes started by an agent. A process started by a natively installed Claude Code used to escape it, and could ask the service for admin access; it no longer can. Admin `deckd` commands run inside Claude Code or Codex are refused: run them from a terminal of your own. Hooks and Claude Channels keep working.
- **The local TCP door is off by default.** It stays on while old `http` Claude hooks may still use it, and it will be removed in the next release.
- **Claude usage on the deck's Usage face is now opt-in.**
- **No more recording from the Mac's microphone.** When the deck's microphone cannot be used, the service no longer falls back to the Mac's.
- **No more repeated Keychain dialog.** The Keychain dialog that kept returning when Claude usage was read should stop.

## Fixes

- The deck could speak the previous turn's answer.
- An order that could not be delivered now shows as **Not delivered** or **Unconfirmed** on the deck.
- Kokoro voice downloads failed.
- Stale Claude channel helpers retried forever.

## Update

- **Mac:** choose **Check for Updates…**, or install the signed, notarized **0.14.0** app for Apple Silicon or Intel; macOS 13 or later is required. If the service still reports an older version, open **Service** and choose **Restart**.
- **Deck:** with the deck connected by USB, open **Service → Updates**, choose **Check** beside the deck, then **Review…** and **Install**. This update is confirmed in the app; later ones are confirmed on the deck. The regular update preserves settings and Bluetooth pairing, while factory images are for manufacturing and overwrite them.
- **Windows:** download the ZIP from this release and follow the Windows guide.
- **Omarchy:** build from this release's source and follow the Omarchy guide.

## Validation

- **Automated:** every change ran the macOS, Linux and Windows host tests, and the firmware tests for LilyGo, Rev A and Rev B.
- **On hardware:**
  - Omarchy with a Rev B over Bluetooth: Superwhisper recognition, spoken replies and the uinput shortcuts.
  - Windows 11: a firmware install over USB, and speech through the deck's speaker.
  - A Mac with a Rev B: a Grok Bot press and its reply.
