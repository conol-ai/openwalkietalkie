OpenWalkieTalkie 0.16.0 只加了一项功能，标为**实验性**，在你打开之前一直是关闭的：
- 在光标处的听写，可以按它要输入的窗口改写（按窗口改写听写）；
- 它用到的模型通过一份服务商列表来访问，每个服务商一把密钥，在伴侣应用里设置一次。

对讲机固件没有变化，仍是 0.14.0。

## 按窗口改写听写（实验性）

说出来的话会被当成普通文字输入。对着终端说 “system CTL status”，输入的是这几个词，而不是 `systemctl status`。打开这项功能后，在光标处的听写（Omarchy 上的 **Dictate** 条目）会先改写再输入：

- **窗口识别模型**读取当前窗口的应用名和标题，只是纯文本，别的都不读（从不截图，也不读窗口内容），并判断这是哪类地方：终端、助手、编辑器、聊天还是普通文字；
- **改写模型**按这类地方改写你说的话。

你说的话会发给改写模型的服务商；窗口的应用名和标题会发给窗口识别模型的服务商。没有选窗口识别模型时，由内置规则根据应用名判断。

它**默认关闭**。在伴侣应用的 **语音 › 按窗口改写听写** 里打开，并选好两个模型。服务的日志会记录每次听写的结果、长度和用时，从不记录说的内容。

### 时间限制

使用云端模型的一次听写，两次调用加起来有 **3 秒**。模型比这慢、出错，或者回答的内容不像改写结果时，会按听到的原样输入。在本机或你自己网络里的模型有更长的时间：默认 15 秒，最多 60 秒。选择器会把这些模型标为 **本地 · 较慢**。已知没有在运行的本地模型不会等待。

### 为什么是实验性

已经证实的和还没有证实的：

- CI 为这个版本在 macOS、Windows 和 Linux 上构建了服务和应用，三处的测试都通过了，所以三个窗口读取部分（Hyprland、macOS、Windows）各自都能在自己的系统上编译。只有 Hyprland 的那个读过真实的窗口。
- 还没有用这个版本的代码，在对讲机上从头到尾证实过一次真实听写被正确改写。
- 还没有用过在你自己电脑上运行的模型，只用过替身。
- Anthropic 的接口只对替身试过，从没对真实服务试过。
- macOS 和 Windows 上还没有 **Dictate** 条目，所以在那里这项功能没有可改写的内容。

这些都补上之后，实验性标记才会去掉。

## 模型接入

伴侣应用在 **语音** 下有一个新页面 **模型接入**：你的模型来自的服务商列表。每个服务商一把密钥，存在操作系统的密钥库里（没有密钥库时，存在只有你能读的文件里），从不写进 `config.toml`。页面只显示每把密钥的最后四个字符。

服务商使用两种协议之一：OpenAI 兼容的 chat completions（OpenAI、OpenRouter、Ollama，以及你给出地址的任何兼容服务器），或 Anthropic 的 Messages API。列表里也有 ElevenLabs，只用于云端语音。在 Omarchy 上，Omarchy 自己的本地模型会被自动找到，不需要设置。模型列表是内置的，也可以从服务商刷新。

在 Linux 上，服务启动时会把云端语音的密钥从 `config.toml` 移到密钥库里。

## 更新

在 Mac 上选择 **检查更新…**，或者安装已签名、已公证的 **0.16.0** 应用（Apple 芯片或 Intel，macOS 13 及以上）。在 Windows 上，从发布页下载 ZIP。在 Omarchy 上，拉取代码，构建服务和应用，再用这两个文件运行 `install.sh`，步骤见 [Omarchy 指南](https://openwalkietalkie.org/docs/omarchy/)。这个版本不需要更新对讲机固件。
