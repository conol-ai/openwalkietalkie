OpenWalkieTalkie 0.11.0 brings native Conol conversations to the deck and Mac app, and opens the same companion interface to other applications.

## Conol on the deck

With a compatible Conol desktop app running and signed in, your chats appear under **Conol**, with its robot mosaic and a **+ New chat** launcher. Select a conversation to read recent public messages, then hold PTT to dictate a follow-up. Dictating into the launcher creates a chat and opens it on the deck.

Conol can present AskUser forms and workflow approvals as a sequence of questions: paged choices, multiple selections, dictated text, and a final review with editing and explicit submission. Unsupported forms open in Conol. Draft answers survive a companion socket reconnect.

The session panel reports the conversation's actual model and thinking effort. Conol currently reports these as read-only; changes remain in Conol. Public user and assistant text is mirrored; images, tool output and private reasoning stay in the owning app.

The integration is local to the two desktop apps. Conol discovers the OpenWalkieTalkie service automatically; no terminal hook or separate model API key is needed. The browser version of Conol does not connect to the local service. Update Conol to a build that includes its OpenWalkieTalkie bridge, as well as updating OpenWalkieTalkie.

## A public interface for native companions

Any application can use the same JSON-RPC methods. `agent.companion.set` supplies application/account grouping and launcher/session roles. `agent.session.set` reports model and effort controls, either read-only or editable. Editable settings are confirmed by the owning app against the exact requested revision.

The new [native companion guide](https://openwalkietalkie.org/docs/native-companions/) covers discovery, registration, conversation updates, forms, settings and reconnects. It includes a [standalone Python example](https://openwalkietalkie.org/examples/native_companion.py) using `kind: other` and the [generated API reference](https://openwalkietalkie.org/docs/deckd-api.md). The example is scripted and requires no Conol installation or model API key.

## Reliable new-chat focus

When a new chat replaces a device slot, the service now sends the slot removal and new occupant before focus. The deck follows an explicit companion selection immediately after PTT release, defers it while an input is held, and cancels deferred focus when you navigate elsewhere. An unfinished question remains open.

The shared eight-slot limit remains. Opening an overflow companion chat can replace an unpinned sibling owned by the same connection, application and account; launchers and other accounts' busy conversations are preserved.

## Update

Install the signed, notarized Mac app for Apple Silicon or Intel, or choose **Check for Updates**. macOS 13 or later is required. Connect the deck over USB-C and choose **Service → Updates → Check firmware**. The app, service and firmware all report **0.11.0**. If an older service is still running, choose **Service → Restart**.

Update both the Mac service and firmware for native companion support. Normal application updates preserve settings and Bluetooth pairing. Recovery protocol 2 and the flash layout are unchanged; older bootloaders use the existing guided migration. Board-specific factory ZIPs are for manufacturing and overwrite settings and pairing.

## Validation

Automated coverage includes companion ownership and grouping, slot promotion, exact settings revision confirmation, new-chat focus ordering, held-input behavior, protocol parsing, rendering, and the Python example's forms and reconnects. The release pipeline tests the Mac workspace and all three firmware targets, then builds Rev A/B application, bootstrap and recovery images and signed, notarized Mac packages. Physical Conol conversation and board tests were not repeated for this release.
