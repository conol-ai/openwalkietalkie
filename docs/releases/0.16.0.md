OpenWalkieTalkie 0.16.0 adds one feature, marked **experimental** and off until you turn it on:
- dictation at the cursor can be rewritten for the window it goes into (context aware transcription);
- the models it uses are reached through one list of providers, each with its own key, set up once in the companion app.

The deck's firmware is unchanged: it stays at 0.14.0.

## Context aware transcription (experimental)

Spoken text comes out as prose. Said into a terminal, "system CTL status" is typed as words, not as `systemctl status`. With this feature on, a dictation at the cursor (the **Dictate** entry on Omarchy) is rewritten before it is typed:

- a **window recognition model** reads the focused window's app name and title, as plain text and nothing else (never a screenshot or the window's contents), and names what kind of place it is: a shell, an agent, an editor, a chat or prose;
- a **rewriting model** rewrites the dictated words for that place.

The dictated words are sent to the rewriting model's provider. The window's app name and title are sent to the window recognition model's provider. Without a window recognition model, built-in rules decide from the app's name.

It is **off by default**. Turn it on, and choose both models, in the companion app under **Voice › Context aware transcription**. The service's log records each dictation's outcome, lengths and timings, never the words.

### Time limits

A dictation using cloud models has **3 seconds** for both calls together. When a model is slower than that, fails, or answers with something that does not look like a rewrite, your words are typed exactly as heard. A model on this computer or your own network is given longer: 15 seconds by default, never more than 60. The pickers mark those models **Local · slower**. A local model known not to be running is not waited for at all.

### Why it is experimental

What has been shown, and what has not:

- CI built the service and the app on macOS, Windows and Linux for this release and their tests passed on all three, so each of the three window readers (Hyprland, macOS, Windows) compiles on its own system. Only the Hyprland one has been seen reading a real window.
- No real dictation on the deck has yet been shown to be rewritten correctly end to end with this release's code.
- No model running on your own computer has been used yet, only stand-ins for one.
- Anthropic's API has only been tried against a stand-in, never the real service.
- There is no **Dictate** entry on macOS or Windows yet, so there the feature has nothing to rewrite.

The badge comes off when those gaps are closed.

## Model access

The companion app has a new page under **Voice**, **Model access**: the list of providers your models come from. Each provider has one key, kept in the operating system's key store (or, where there is none, a file only you can read), never in `config.toml`. The page shows each key only by its last four characters.

Providers speak one of two protocols: OpenAI-compatible chat completions (OpenAI, OpenRouter, Ollama, any compatible server at an address you give) or Anthropic's Messages API. ElevenLabs is listed too, for the cloud voice only. On Omarchy, Omarchy's own local models are found by themselves and need no setup. Model lists are built in and can be refreshed from the provider.

On Linux, the cloud voice's key moves out of `config.toml` into the key store when the service starts.

## Update

On a Mac, choose **Check for Updates…**, or install the signed, notarized **0.16.0** app for Apple Silicon or Intel (macOS 13 or later). On Windows, download the ZIP from the release. On Omarchy, pull, build the service and the app, and run `install.sh` with both, as the [Omarchy guide](https://openwalkietalkie.org/docs/omarchy/) shows. The deck needs no firmware update for this release.
