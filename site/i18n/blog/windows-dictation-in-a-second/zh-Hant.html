0.17.0 版只修正了一件事：Windows 上的口述。在 Windows 預覽版上，按下 PTT 說話得不到任何文字，因為語音辨識還沒完成就逾時了。現在大約一秒就能完成。裝置韌體不變，仍是 0.14.0，macOS 與 Omarchy 上沒有變化。

兩個原因

在 Windows 上，Whisper 在 CPU 上執行。發行組建編譯 whisper.cpp 時完全沒有開啟最佳化：使用 Visual Studio 產生器時，cmake crate 會用不含 /O2 的參數覆寫發行版的編譯參數。而且 Windows 用的是適合 Metal 的 Mac 解碼設定：按 2 秒，編碼器也要跑完整個 30 秒視窗，失敗的一遍還會用更高的溫度重新解碼。兩者疊加，一次很短的按鍵也可能超過一次口述的 30 秒時限。

改了什麼

Windows 的發行組建現在會設定 CMAKE_C_FLAGS_RELEASE 與 CMAKE_CXX_FLAGS_RELEASE，whisper.cpp 會以最佳化方式編譯。在 Windows 上，和 Linux 一樣，Whisper 只解碼一遍，只編碼這次按鍵需要的那部分視窗。模型載入時，服務的記錄會寫下 whisper.cpp 編譯時啟用的 CPU 功能。

實測

在一台 Intel Core i5-13420H 的測試電腦上，使用 ggml-small.bin 模型，說同一句普通話「收到，已经下发了。」，試了三個組建。發行的 0.16.0 沒有任何文字：兩次按鍵，分別用 small 與 large-v3-turbo-q5_0，都在 30,000 毫秒後逾時。只修正解碼設定、whisper.cpp 仍未最佳化時，17,242 毫秒後出字。兩項都修正後，1,124 毫秒出字，比同一顆 CPU 上的參考實作 whisper-cli 還快。辨識結果是 收到已经下发了（簡體字）：七個字全部正確，順序也對，只是少了逗號與句號。

自己組建

本機的 Windows 組建也必須設定這兩個變數，在 PowerShell 中設為 /O2 /Ob2 /DNDEBUG，在 Git Bash 中設為 -O2 -Ob2 -DNDEBUG，否則 whisper.cpp 又會在沒有最佳化的情況下編譯。實際指令見版本說明。

更新

在 Windows 上，依照 Windows 指南從版本頁面下載 ZIP。在 Mac 上，選擇檢查更新…，或安裝已簽署並經過公證的 0.17.0 應用程式（Apple Silicon 或 Intel，macOS 13 或更新版本）。在 Omarchy 上，拉取程式碼，建置服務與應用程式，再用這兩者執行 install.sh，詳見 Omarchy 指南。這個版本不需要更新裝置韌體。
