0.17.0 で直したのは 1 つだけ、Windows での口述です。Windows プレビュー版では、PTT を押して話しても文字が出ませんでした。音声認識が終わる前に時間切れになっていたためです。今は約 1 秒で終わります。デバイスのファームウェアは 0.14.0 のまま変わらず、macOS と Omarchy にも変更はありません。

2 つの原因

Windows では Whisper は CPU で動きます。リリースビルドは whisper.cpp をまったく最適化せずにコンパイルしていました。Visual Studio ジェネレーターでは、cmake クレートがリリース用のコンパイラフラグを /O2 を含まないものに上書きするためです。さらに Windows は、Metal 向けの Mac のデコード設定を使っていました。2 秒の押下でもエンコーダーは 30 秒のウィンドウ全体を処理し、失敗したパスはより高い温度でもう一度デコードされていました。この 2 つが重なり、短い押下でも口述に与えられる 30 秒を超えることがありました。

変更点

Windows のリリースビルドは CMAKE_C_FLAGS_RELEASE と CMAKE_CXX_FLAGS_RELEASE を設定するようになり、whisper.cpp は最適化してコンパイルされます。Windows でも Linux と同じく、Whisper のデコードは 1 回だけで、押下に必要な分だけのウィンドウをエンコードします。モデルを読み込むと、whisper.cpp がどの CPU 機能でコンパイルされたかをサービスのログに記録します。

測定結果

Intel Core i5-13420H のテスト用 PC で、ggml-small.bin モデルを使い、同じ中国語（普通話）の文「收到，已经下发了。」で 3 つのビルドを試しました。リリースされた 0.16.0 では文字がまったく出ませんでした。small と large-v3-turbo-q5_0 で 1 回ずつ押し、どちらも 30,000 ms で時間切れになりました。デコード設定だけを直し、whisper.cpp が最適化なしのままだと、文字が出るまで 17,242 ms でした。両方を直すと 1,124 ms で、同じ CPU で動かした参照実装の whisper-cli より速くなりました。認識結果は 收到已经下发了 で、7 文字すべてが正しく、順番どおりでした。読点と句点は出ませんでした。

自分でビルドする場合

ローカルの Windows ビルドでも同じ 2 つの変数を設定する必要があります。PowerShell では /O2 /Ob2 /DNDEBUG、Git Bash では -O2 -Ob2 -DNDEBUG です。設定しないと whisper.cpp はまた最適化なしでコンパイルされます。コマンドはリリースノートにあります。

アップデート

Windows では、Windows のガイドのとおりにリリースから ZIP をダウンロードします。Mac ではアップデートを確認…を選ぶか、署名・公証済みの 0.17.0 のアプリ（Apple シリコン用または Intel 用、macOS 13 以降）をインストールします。Omarchy では、Omarchy のガイドのとおりに、最新のコードを取得してサービスとアプリをビルドし、両方で install.sh を実行します。このリリースではデバイスのファームウェアの更新は不要です。
