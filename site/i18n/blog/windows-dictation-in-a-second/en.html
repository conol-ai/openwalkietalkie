Version 0.17.0 fixes one thing: dictation on Windows. On the Windows preview, a press of PTT produced no text, because the speech recogniser ran out of time before it finished. It now finishes in about a second. The deck's firmware is unchanged at 0.14.0, and nothing changes on macOS or Omarchy.

Two causes

On Windows, Whisper runs on the CPU. The release build compiled whisper.cpp with no optimisation at all: under the Visual Studio generator, the cmake crate overwrites the release compiler flags with ones that carry no /O2. And Windows used the Mac's decode settings, which suit Metal: the encoder ran its full 30-second window for a 2-second press, and a failed pass was decoded again at a higher temperature. Together, a short press could take longer than the 30 seconds a dictation is given.

What changed

The Windows release build now sets CMAKE_C_FLAGS_RELEASE and CMAKE_CXX_FLAGS_RELEASE, so whisper.cpp is compiled optimised. On Windows, as on Linux, Whisper makes one pass and encodes only as much of its window as the press needs. When the model loads, the service's log records which CPU features whisper.cpp was compiled with.

Measured

On a test PC with an Intel Core i5-13420H, the ggml-small.bin model and the Mandarin sentence 「收到，已经下发了。」, three builds were tried. 0.16.0 as shipped produced nothing: two presses, with small and with large-v3-turbo-q5_0, both timed out after 30,000 ms. With the decode settings fixed but whisper.cpp still unoptimised, the text came out after 17,242 ms. With both fixes, it came out after 1,124 ms, faster than the reference whisper-cli on the same CPU. The transcript was 收到已经下发了: all seven characters correct and in order, without the comma and the full stop.

Building it yourself

A local Windows build must set the same two variables, /O2 /Ob2 /DNDEBUG in PowerShell or -O2 -Ob2 -DNDEBUG in Git Bash, or whisper.cpp is compiled unoptimised again. The release notes show the commands.

Update

On Windows, download the ZIP from the release, as the Windows guide shows. On a Mac, choose Check for Updates…, or install the signed, notarized 0.17.0 app for Apple Silicon or Intel (macOS 13 or later). On Omarchy, pull, build the service and the app, and run install.sh with both, as the Omarchy guide shows. The deck needs no firmware update for this release.
