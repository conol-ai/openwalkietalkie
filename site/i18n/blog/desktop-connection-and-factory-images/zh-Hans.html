OpenWalkieTalkie 0.5.0 修复了 Codex Desktop 与对讲机之间的连接，还增加了对两种替代闪存芯片的固件支持，并提供用于工厂烧录的整片镜像。

桌面任务已传递至共享服务

旧启动器虽然能打开 Codex Desktop，却可能让 OpenWalkieTalkie 看不到其中的对话。原因是 Desktop 的默认插件设置，让隐式共享服务模式回退到了独立的私有服务。更新后的启动器会明确选择共享的本地连接。

兼容的已安装应用，无论名为 ChatGPT.app 还是 Codex.app，都能被识别。启动器会复用现有的 Codex 服务，不影响 Desktop 中正在进行的任务。此外，还修复了短任务的回复丢失问题：即使任务在 OpenWalkieTalkie 订阅对话前就已完成，也能收到回复。

更新后修复集成

安装 0.5.0 版本应用并确认其服务也报告 0.5.0 版本。打开 Integrations → Codex Desktop 并安装或修复该集成。当你的桌面任务空闲时，退出 Codex 桌面版 / ChatGPT，然后打开 ~/Applications/Codex with OpenWalkieTalkie.app。

这是一个用于启动已安装桌面版应用的启动器。今后也请使用它来启动：直接打开原始应用不会启用共享连接。不支持的桌面版构建会报错，而不是静默地打开一个未连接到配套服务的会话。

更多闪存选项和出厂镜像

固件现在支持 Puya PY25Q128HA-SUH-IR (C5354566) 和 GigaDevice GD25Q128ESIGR (C2928891)，以及原有的 Winbond W25Q128JVSIQ (C97521)。其设置、配对和引导程序写入功能会在启用写入前验证稳定的芯片 ID。使用替代型号的板子仍需进行物理验证。

发布包包含出厂 ZIP 包，其中分别提供 Rev A 和 Rev B 的 16 MiB 整片镜像。每份镜像都将正式发布的应用固件、恢复固件、新闪存分区表和空白设备存储区组合在一起，并附带中文说明、各组成文件的哈希值和独立校验工具。

出厂镜像将覆盖所有闪存内容，包括设置和配对数据。 它们仅用于新板子的初始化配置。已有设备应使用应用的正常 USB 更新工具。

更新现有对讲机

连接一台对讲机到 USB-C，然后打开 Service → Updates → Check firmware。分区布局和恢复协议与 0.4.0 版本保持一致，因此已处于恢复协议 2 的设备将接收正常的应用更新。

仍使用旧引导程序的设备需要按向导迁移。请保持供电，并让 Mac 保持唤醒：替换引导程序时断电可能导致无法启动、无法通过 USB 恢复，甚至需要硬件维修。软件会在迁移前显示这条警告。不要把 bootstrap 或 recovery 文件当作应用固件手动安装。

已验证的内容

启动器和传输回归测试通过。在开发用 Mac 上进行的现场测试中，桌面端连接到共享服务，其 DESKTOP-LINK-OK 响应出现在 OpenWalkieTalkie 图形用户界面中。连接的 Rev A 设备通过 USB 传输数据正常；最终的物理屏幕检查未被记录。

两种板型都通过了软件检查。之前支持相同闪存的 0.4.1 开发固件，已在现有 Rev A 上完成旧引导程序迁移；那次测试没有刷入 CI 构建的 0.5.0 文件。出货版 Rev B、使用替代闪存芯片的电路板，以及空白板的出厂烧录，仍需硬件验证。本次没有进行设备音频测试。

获取 v0.5.0

使用 Check for Updates 或 从官网下载已签名并通过公证的 Mac 应用程序，适用于 Apple Silicon 或 Intel。需要 macOS 13 或更高版本。

本次 GitHub 版本发布 包含固件、出厂镜像、校验和、构建认证信息以及一份中文升级指南。该指南也包含在每个 DMG 文件中。
