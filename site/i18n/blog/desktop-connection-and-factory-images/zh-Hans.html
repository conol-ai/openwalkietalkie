OpenWalkieTalkie 0.5.0 修复了 Codex Desktop 与设备之间的连接。它还在固件中加入了对两款替代闪存芯片的支持，并打包了用于工厂烧录的整片出厂固件。

Desktop 的任务能到达共享服务了

之前的启动器能成功打开 Desktop，但它的对话对 OpenWalkieTalkie 不可见。Desktop 的默认插件设置让它隐式的共享服务模式退回到私有服务器。更新后的启动器会明确选择共享的本地连接。

名为 ChatGPT.app 或 Codex.app 的兼容安装都能被识别。启动器会复用现有的 Codex 服务，不会干扰正在运行的 Desktop 任务。另一项修复让那些在 OpenWalkieTalkie 订阅其对话之前就已完成的简短任务，也能正常送回回复。

更新后修复集成

安装 0.5.0 版应用，并确认它的服务也显示 0.5.0。打开 集成 → Codex Desktop，安装或修复这项集成。等 Desktop 的任务空闲时，退出 Codex Desktop / ChatGPT，然后打开 ~/Applications/Codex with OpenWalkieTalkie.app。

这是一个用来启动你已安装的 Desktop 应用的小启动器。以后也请用它来启动：直接打开原来的应用不会启用共享连接。不受支持的 Desktop 版本会报错，而不是悄悄打开一个未连接的会话。

更多闪存选择和出厂固件

除了原有的 Winbond W25Q128JVSIQ（C97521），固件现在也接受 Puya PY25Q128HA-SUH-IR（C5354566）和 GigaDevice GD25Q128ESIGR（C2928891）。设置、配对和引导程序的写入程序在允许写入之前，会先确认读到的是稳定且受支持的芯片 ID。贴装了替代芯片的主板仍需实机验证。

这个版本附带一个出厂 ZIP，其中 Rev A 和 Rev B 各有一个独立的 16 MiB 镜像。每个镜像都由与发布版本完全相同的应用程序和恢复二进制文件、一份全新的分区表以及空的设备存储区组成。随附中文说明、各组件的哈希值和一个独立的校验工具。

出厂固件会覆盖闪存中的全部内容，包括设置和配对数据。它用于空白主板的初次烧录。已在使用的设备应使用应用中常规的 USB 更新程序。

更新已有的设备

通过 USB-C 连接一台设备，然后打开 服务 → 更新 → 检查固件更新。分区布局和恢复协议与 0.4.0 相同，因此已使用恢复协议 2 的设备会收到普通的应用程序更新。

仍在使用旧引导程序的设备需要进行引导式迁移。请保持供电，并让 Mac 保持唤醒：替换引导程序时断电，可能导致设备无法启动、无法通过 USB 恢复，只能进行硬件维修。应用会在迁移前显示这条警告。不要把 bootstrap 或 recovery 文件当作应用程序固件手动安装。

我们验证了什么

启动器和传输的回归测试均已通过。在开发用 Mac 上的实际测试中，Desktop 连接到了共享服务，它的 DESKTOP-LINK-OK 回复出现在 OpenWalkieTalkie 的图形界面中。通过 USB 向已连接的 Rev A 发送正常；最后在实机屏幕上的检查没有记录下来。

两种主板版本都通过了软件检查。之前带有相同闪存支持的 0.4.1 开发版固件，在现有的 Rev A 上完成了从旧引导程序的迁移。该测试中没有刷写 CI 构建的 0.5.0 文件。已出货的 Rev B、使用替代芯片的主板以及空白主板的工厂烧录，仍需硬件验证。没有进行设备音频测试。

获取 v0.5.0

使用 检查更新，或下载已签名并经过公证的 Mac 应用，支持 Apple Silicon 和 Intel。需要 macOS 13 或更高版本。

GitHub 发布版本包含固件、出厂固件、校验和、构建证明以及中文升级指南。每个 DMG 中也附有这份指南。
