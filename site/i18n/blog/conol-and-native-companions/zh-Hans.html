0.11.0 将对讲机接入 Conol 桌面应用的对话。你可以在手持设备上打开聊天、查看最近消息、用语音追问或回答问题。同一套本地原生应用接入接口也开放给其他应用。

在对讲机上集中查看 Conol 对话

启动兼容版本的 Conol 桌面应用并登录后，对话会显示在 Conol 分组下，带有机器人像素图标和 + New chat 新建对话入口。选一个对话，就能查看最近的用户可见消息。按住 PTT 可以继续追问；选中新建对话入口后说话，则会创建新对话。

创建聊天后会自动在对讲机上打开，准备接收下一条消息。Conol 会自动发现本地 OpenWalkieTalkie 服务，无需配置终端钩子或额外模型 API 密钥进行配置。此连接需要 Conol 桌面应用及其 OpenWalkieTalkie 桥接服务；浏览器版本无法连接到本地服务。

从手持设备回答整个表单

Conol 可以逐条展示 AskUser 表单和工作流审批。逐页浏览单选选项，切换多选，口述自由文本答案，然后审查并编辑，最后明确提交完整表单。应用通过套接字重新连接后，草稿答案仍会保留。无法在该交互中完成的表单将直接在 Conol 中打开。

会话面板显示当前对话实际使用的模型和思考强度。对于 Conol，这两项目前只能在对讲机上查看，需要回到 Conol 中修改。对话记录只同步用户可见的用户和助手文字；图片、工具输出及内部推理仍留在原应用中。

对其他应用开放

这项集成使用公开的 JSON-RPC 接口。应用可通过 agent.companion.set 设置分组和新建对话入口，发布消息和问题，并通过 agent.session.set 上报实际使用的模型和思考强度。支持修改设置的应用，需要核对请求对应的精确修订号，再确认每次变更。

新的原生应用接入指南介绍了服务发现、注册、对话记录、表单、设置和断线重连。可以试试独立 Python 示例：它使用预设回复，不需要模型 API 密钥，也不需要安装 Conol。自动生成的 API 参考文档列出了请求结构和权限。

保持新聊天的焦点

当一个会话槽位被替换时，服务现在会先公布新会话，再将焦点切过去。配套应用明确要求选中某个会话时，对讲机会在松开 PTT 后立即跟随；如果按键等输入尚未释放，就先等待；如果你已经手动导航到别处，则以你的操作为准。尚未完成的问题会继续保持打开。

会话槽位仍共用八个名额。打开超出名额的原生应用对话时，可以替换同一连接、同一应用、同一账号下未固定的其他对话，但会保留新建对话入口，以及其他账号中正在工作的对话。

升级到 0.11.0

安装适合 Apple Silicon 或 Intel 的 Mac 应用，安装包已签名并通过公证；已有安装可选择 Check for Updates。需要 macOS 13 或以上版本。用 USB-C 连接对讲机，选择 Service → Updates → Check firmware。Mac 服务和固件都需要达到 0.11.0，才能支持原生应用接入。如果旧服务仍在运行，选择 Service → Restart。同时将 Conol 更新到带有 OpenWalkieTalkie 桥接功能的版本。

正常更新保留设置和蓝牙配对。恢复协议 2 和闪存布局保持不变。独立的工厂 ZIP 文件用于制造流程，会覆盖设置和配对。

自动化覆盖检查包含所有权、分组、槽位提升、设置确认、焦点排序、保持输入、协议解析、渲染，以及示例中的表单和重新连接。本次版本未重复进行真实 Conol 对话和板级测试。
