0.16.0 版只新增了一項功能，而且是實驗性的：在游標處口述的內容，可以依它要進入的視窗改寫。在你開啟之前，它是關閉的。裝置韌體不變，仍是 0.14.0。

問題

說出來的話會變成一般文字。在終端機上按住 PTT 說「system CTL status」，輸入的就是「System CTL status」這幾個字，而不是 systemctl status。你真正想要的，取決於這些字要去哪裡，而口述並不知道。

它做什麼

開啟這項功能後，在游標處的口述（Omarchy 上的 Dictate 項目）會在輸入之前先被改寫。視窗辨識模型會讀取聚焦視窗的應用程式名稱與標題，只有這兩項純文字，沒有別的：絕不截圖，也絕不讀取視窗內容。它判斷那是什麼樣的地方：shell、助理、編輯器、聊天，或一般文字。接著改寫模型會為那裡改寫你的話。沒有視窗辨識模型時，由內建規則依應用程式名稱判斷。

你口述的話會送給改寫模型的服務商，應用程式名稱與標題則送給視窗辨識模型的服務商。服務的記錄只會記下每次口述的結果、長度與耗時，絕不記錄內容。請在配套應用程式的語音 › 按視窗改寫聽寫中開啟這項功能，並選擇兩個模型。

三秒，否則照原話輸入

使用雲端模型的口述，兩次呼叫加起來只有 3 秒。如果模型比這更慢、發生錯誤，或回答的內容看起來不像改寫，就會照你說的原話輸入。在這台電腦或你自己網路上的模型會得到較長的時間，預設 15 秒，最多 60 秒，選擇器會把它標示為本機 · 較慢。已知沒有在執行的本機模型不會被等待。

模型接入

這些模型來自語音下的一個新頁面：模型接入。這裡是一份服務商清單，每個服務商一把金鑰，保存在作業系統的金鑰儲存區中，絕不寫進 config.toml。頁面只會顯示金鑰的最後四個字元。服務商使用兩種協定之一：相容 OpenAI 的 chat completions（OpenAI、OpenRouter、Ollama，或你提供位址的任何相容伺服器），或 Anthropic 的 Messages API。ElevenLabs 只用於雲端語音。在 Omarchy 上，它自己的本機模型會被自動找到。

為什麼是實驗性的

有三件事還沒有得到證實。在這個版本之前，macOS 與 Windows 的部分從未建置過；0.16.0 的 CI 在這兩個系統上建置並測試了它們，但只有 Hyprland 的視窗讀取器讀過真實的視窗。還沒有用過在你自己電腦上執行的模型，只用過模擬的替身。Anthropic 的 API 也只對替身試過，從未對真正的服務試過。還沒有證實裝置上真實的口述能用這套程式碼從頭到尾正確改寫，而且 macOS 與 Windows 還沒有 Dictate 項目，所以在那裡這項功能沒有東西可以改寫。

更新

在 Mac 上，選擇檢查更新…，或安裝已簽署並經過公證的 0.16.0 應用程式（Apple Silicon 或 Intel，macOS 13 或更新版本）。在 Windows 上，從版本頁面下載 ZIP。在 Omarchy 上，拉取程式碼，建置服務與應用程式，再用這兩者執行 install.sh，詳見 Omarchy 指南。這個版本不需要更新裝置韌體。
