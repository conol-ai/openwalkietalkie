0.10.0 在订阅用量统计之外新增了 System（系统）界面，实时显示正在工作的电脑状态。查看 CPU 负载、内存、GPU 负载和剩余存储空间，不必再打开一个窗口遮住编辑器。

四项指标，每两秒更新一次

Mac 服务会采集 CPU 总使用率、已用及总内存、GPU 使用率，以及可写启动卷的剩余和总空间。CPU 数据按全部核心归一化；内存包括应用内存、联动内存（必须驻留在 RAM 中）和压缩内存。Mac 有多个图形加速器时，GPU 指标显示负载最高的那个。

存储百分比表示剩余空间，空间不足时会改变颜色。无法获取的指标显示 Not available；超过十秒未更新的读数会变灰，并标为 STALE；与电脑断开连接时显示 OFFLINE。CPU 使用率需要采样两次才能算出首个结果。

数据每两秒更新一次，数值没有变化的区域不会重绘。System 只出现在对讲机上，Mac 软件没有新增页面；订阅额度仍在 Usage（用量统计）中查看。

如何找到它

在全新的默认布局中，System 排在 Usage 后面。更新会保留已有布局；要添加它，按双击 Shift → + → System → Enter操作。固件和 Mac 服务都需要更新。如果旧服务仍在运行，点击 Service → Restart。

像素小鸟减少了屏幕重绘

像素小鸟现在只刷新小鸟、管道和分数所在的区域，不再每推进一步游戏逻辑就让整屏重新绘制。显示管线已能正确打包局部矩形区域，兼容旋转安装的 Rev A 和 Rev B 屏幕；帧计时也会扣除已经花在渲染上的时间。

在包含多个管道及管道复用的 360 帧渲染测试中，平均传输的像素量减少了 51.5%。这个数字衡量的是传输区域大小，并不代表设备上的帧率提升。测试会在得分变化、暂停和游戏结束等状态下，将局部重绘与完整重绘进行比较。TE 同步仍未启用，因此不保证动画完全没有画面撕裂。

更长的音乐，有了完整的起承转合

三款游戏的原创合成音乐现在每首都有 48 小节：像素小鸟 96 秒、贪吃蛇 115.2 秒、雷电 76.8 秒。前奏之后是主题、与主题呼应的旋律和较安静的段落，最后回到主题；低音、打击乐和脉冲音色也随之变化。

暂停或重玩同一款游戏时，会保留音乐的播放进度；换一个游戏，才从新游戏的主题音乐开始。通过 Arcade → Sound → Enter 选择 Off（关闭）、SFX only（仅音效）或 Music + SFX（音乐和音效）。

更新到 0.10.0

安装已签名并通过公证的 Mac 软件，按机型选择 Apple Silicon 或 Intel 版；也可以选择 Check for Updates（检查更新）。需要 macOS 13 及以上。通过 USB-C 连接对讲机，再打开 Service → Updates → Check firmware。软件、服务和固件的版本应都显示为 0.10.0。

正常应用更新保留设置和蓝牙配对。较旧的引导程序使用现有的引导迁移流程。单独的工厂 ZIP 文件用于制造用途，会覆盖现有设置和配对。

已在 Rev A 上通过 USB 刷入并验证 0.10.0 固件，随后重启了设备，Mac 采样器返回了全部四项指标。自动化检查涵盖消息验证、兼容性、数据时效性、渲染、模拟时序和音乐连续性。Rev B 硬件和物理断电恢复未在此功能中重新测试。
