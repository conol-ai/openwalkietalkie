OpenWalkieTalkie 0.4.0 為裝置的功能騰出更多空間，並讓韌體復原過程直接顯示在裝置上。它也新增了中文文字支援，Codex 的提問與回答也變得更清楚。

應用程式可用的快閃記憶體變多了

16 MiB 的 NOR 快閃記憶體現在有 15.75 MiB 可用於應用程式的程式碼與資源。分割表、開機載入程式和兩個藍牙儲存區仍保留各自的空間。中文字型放在應用程式的上半區，讓下半區有更多空間放程式碼。

時脈設定修正後，韌體再次直接從 NOR 快閃記憶體執行，開機時不再把整個應用程式複製到 PSRAM。

復原畫面與更快的 USB 更新

新的開機載入程式會在裝置的螢幕上顯示復原說明、傳輸進度、完成狀態與錯誤。已更新的裝置可以使用稀疏傳輸與管線化的 USB 大量傳輸，略過填充區域的寫入，並保留藍牙儲存區。

從舊開機載入程式進行的第一次升級，仍會先以 HID 傳輸一個暫時的更新程式。這個階段需要好幾分鐘。之後的階段可以使用新的傳輸方式，但快閃記憶體的抹除與寫入時間仍會算進總時間。

從 0.3.0 升級

安裝 0.4.0 版的 Mac 應用程式，用 USB-C 連接線連接一台裝置，然後開啟 服務 → 更新 → 檢查韌體更新。繼續之前，請核對主機板版本與序號。

這次升級可能會替換開機載入程式。在應用程式回報成功之前，請保持 USB-C 供電，並讓 Mac 維持喚醒。替換開機載入程式時斷電，可能讓裝置既無法開機也無法透過 USB 復原，必須送硬體維修。應用程式會顯示這則警告，並要求你明確確認後才開始遷移。

應用程式會安裝一個暫時的更新程式，備份並替換開機載入程式，讀回內容以驗證寫入，然後安裝最終的韌體。請使用這個引導式流程，不要手動燒錄 bootstrap 或 recovery 檔案。更新程式不會改寫分割表，也會略過藍牙儲存區。

完成後，裝置的「關於」頁面應顯示 0.4.0 · Rev A 或 0.4.0 · Rev B。版本標籤現在會自動跟著韌體的建置版本。兩種主機板版本的韌體與經過驗證的資訊清單都隨附在應用程式中，因此離線時也能更新韌體。

中文文字與更清楚的助理對話

內建的 Noto Sans CJK 字型新增了簡體與繁體中文的支援。Codex 的釐清提問與回答會以易讀的標題、問題脈絡與回答文字呈現，而不再顯示其傳輸封裝。這個版本也包含 0.3.0 之後加入的 Codex Desktop 整合與藍牙訊號強度指示。

已經測試的項目

兩種主機板版本都能建置，並通過軟體檢查。較早的 0.3.1 候選版本在 Rev A 上完成了從原始 0.3.0 到新開機載入程式的完整圖形介面遷移，大約花了五分半鐘，使用的復原程式來源相同。CI 重新建置的發行版本產生的開機載入程式位元組不同，尚未在該測試中燒錄。

0.4.0 最終版的圖形介面重測在燒錄前就被本機的桌面自動化擋下。手邊沒有已出貨的 Rev B，因此它的完整遷移、顯示表現，以及配對與設定能否保留，仍有待在硬體上檢查。這些是尚待進行的檢查，不是已完成的驗證。本次沒有進行裝置音訊測試。

取得 v0.4.0

使用 檢查更新，或下載已簽署並經過公證的 Mac 應用程式，支援 Apple Silicon 與 Intel。需要 macOS 13 或更新版本。

GitHub 發行版本包含韌體、檢查碼與中文升級指南。DMG 中也附有同一份指南。
