OpenWalkieTalkie v0.11.0: Conol and native companions

October 28, 2026App and firmware update

Version 0.11.0 connects the deck to conversations in the Conol desktop app. Open a chat, read recent messages, dictate a follow-up or answer a question from the handheld. The same local companion interface is available to other applications.

Your Conol conversations, together

With a compatible Conol desktop app running and signed in, chats appear under Conol, with its robot mosaic and a + New chat launcher. Choose a conversation to see recent public user and assistant messages. Hold PTT to dictate a follow-up, or dictate into the launcher to create a new chat.

Creating a chat opens it on the deck, ready for the next message. Conol discovers the local OpenWalkieTalkie service automatically; there is no terminal hook or separate model API key to configure. This connection requires the Conol desktop app with its OpenWalkieTalkie bridge; the browser version does not connect to the local service.

Answer a whole form from the handheld

Conol can present AskUser forms and workflow approvals one question at a time. Page through single choices, toggle multiple selections, dictate a free-text answer, then review and edit before explicitly submitting the complete form. Draft answers survive a companion socket reconnect. Forms that cannot fit this interaction open in Conol.

The session panel shows the conversation's actual model and thinking effort. These are currently read-only for Conol; change them in Conol itself. The transcript mirrors public user and assistant text. Images, tool output and private reasoning remain in the owning app.

Open to other apps

The integration uses a public JSON-RPC interface. An app can supply its own grouping and new-chat launcher through agent.companion.set, publish messages and questions, and report its actual model and effort through agent.session.set. Apps that support editable settings confirm each requested change against its exact revision.

The new native companion guide explains discovery, registration, transcripts, forms, settings and reconnects. Try the standalone Python example: it uses scripted responses, needs no model API key, and works without Conol installed. The generated API reference documents the request schemas and permissions.

Keep the new chat in focus

The service now announces a replaced slot's new occupant before focusing it. The deck follows an explicit companion selection immediately after PTT release, waits while an input is held, and gives way if you navigate elsewhere. An unfinished question stays open.

The shared eight-slot limit remains. Opening an overflow companion chat can replace an unpinned sibling belonging to the same connection, app and account, while preserving launchers and other accounts' busy chats.

Update to 0.11.0

Install the signed, notarized Mac app for Apple Silicon or Intel, or choose Check for Updates. macOS 13 or later is required. Connect the deck over USB-C and choose Service → Updates → Check firmware. Both the Mac service and firmware need 0.11.0 for native companion support. If an older service is still running, choose Service → Restart. Also update Conol to a build with its OpenWalkieTalkie bridge.

Normal updates preserve settings and Bluetooth pairing. Recovery protocol 2 and the flash layout are unchanged. The separate factory ZIPs are for manufacturing and overwrite settings and pairing.

Automated coverage checks ownership, grouping, slot promotion, settings confirmation, focus ordering, held inputs, protocol parsing, rendering, and the example's forms and reconnects. Physical Conol conversation and board tests were not repeated for this release.
