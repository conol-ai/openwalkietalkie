Connect Grok Bot

A routine, a webhook and a key · about ten minutes

Grok Bot works the other way round from the other two. There is no local session to attach: you make a routine in Grok Bot, point it at this machine, and the deck becomes that bot's microphone and screen.

What gets connected

A bot is a row in the app's config file plus a key the system keeps for it. The webhook lives in Grok Bot; the app sends to it and reads what comes back.

  • The bot — a [grokbot.bots.<id>] entry in config.toml: its name, webhook URL and settings.
  • The key — kept by the system, not in that file: Keychain on macOS (service ai.cohdl.openwalkietalkie, account grokbot.bots.<id>.key), Credential Manager on Windows, and grokbot-keys.toml on Linux or in an isolated data directory.
  • The routine — made in Grok Bot, not here. It is what gives you the URL and the key.

1 · Make the routine in Grok Bot

  1. In Grok Bot, open the bot you want and go to Settings → Computer. Allow it to run commands: without that the routine can answer but cannot do anything.
  2. Create a routine, then open the bot's name at the top of the chat → Details → routine → Webhook. It shows a POST to URL and a key.

2 · Add the bot here

  1. Open Integrations → Grok Bot → Bots… → Add Bot.
  2. Give it the name you want on the deck, paste the POST to URL and the key, and press Add Bot.
  3. Press Test: it sends one request to the webhook and tells you whether the routine accepted it.

If the row offers Copy Prompt, that is the same routine described in Grok Bot's own words: send it in the bot's chat and Grok Bot writes the routine for you. Either way you end up with a URL and a key.

3 · What you should see

  • Grok Bot row: Set up with a count of bots; Not set up before the first one.
  • A key is missing means a bot is in the config and the system has no key for it: add the bot again with the routine's current key.
  • On the deck: CANCEL → Agents lists the bot by name, with no chat open anywhere.

When it doesn't work

Grok Bot refused the key (HTTP 401)
The routine was recreated, or its key was rotated. Copy the routine's key again and add the bot again. The same answer applies to HTTP 403.
Grok Bot does not know this webhook (HTTP 404)
The URL points at a routine that no longer exists. Copy the routine's POST to URL again and add the bot again.
A key is missing
The config lists the bot and the system has no key for it. Add the bot again: re-adding the same bot keeps its key unless you supply a new one.
The bot answers but cannot use the computer
Settings → Computer in Grok Bot did not allow it. The routine still runs and the deck still carries the words; nothing gets executed.
Grok Bot did not start a run
The key was accepted, but this run did not start. A paused routine does that — the app asks Is the routine paused? — so resume it in Grok Bot and press Test again.

How this page was checked

Row states and the error strings come from the app and the service source in 0.17.0, and the storage locations from the service's own documentation. No real Grok Bot routine was created against this build: the HTTP answers above are the app's, not observations of a live routine.
