GET STARTED · APP 0.17.0

Get started

macOS, Windows and Linux · about ten minutes

Install the app, connect the deck, connect one coding agent. Three steps, and the deck is a second screen for a session you already have open.

What you need

  • A deck with charge in it.
  • A Mac on macOS 13 or later, a PC on Windows, or Linux (the supported setup is Omarchy).
  • A USB-C data cable. A charge-only cable links nothing.
  • One coding agent already installed and signed in: Claude Code, Codex, or Grok Bot.

1 · Install the app

macOS

  1. Download the disk image for your chip from the download section, open it, and drag OpenWalkieTalkie into Applications.
  2. Launch it from Applications, not from the disk image. A copy run from the image is quarantined by macOS and cannot register the background service.

Windows

  1. Download OpenWalkieTalkie-0.17.0-windows-x86_64.zip from the release page and unpack it to a folder you will keep.
  2. The build is unsigned: SmartScreen shows Windows protected your PC. Choose More info, then Run anyway.

The Windows guide covers the preview, the tray icon and firmware updates over USB-C.

Linux

The supported setup is Omarchy. Build the service and the app, install both, then load the two udev rules for the deck and the virtual keyboard. The Omarchy guide has the commands, and it is the page to follow: this one only tells you where it fits.

2 · Connect the deck

  1. Cable first. Connect the USB-C data cable and allow the accessory if macOS asks. Hold PTT for two seconds to power it on.
  2. Wireless. Pair OpenWalkieTalkie in Bluetooth, and allow Bluetooth for the companion under Privacy & Security → Bluetooth.
  3. Check it. Open Deck → Your deck → Link. A green dot with Cable or Bluetooth means the service can see it.

3 · Start the background service

Open Service. The first card says whether the background service runs; everything else on the deck depends on it.

  • macOS. If it is not running, press Start. If the row says it waits for approval, open Settings and allow it under Login Items: nothing starts until you do.
  • Windows. The service starts at sign-in through a Run key, which Start at login shows and switches.
  • Linux. systemctl --user status deckd. If the unit is not there, the Omarchy guide's installer has not run.

Turn Start at login on before you close the window. A deck with no service is a deck that says offline.

4 · Connect one agent

One is enough to start. Each row on Integrations sets up one agent; the tutorials go step by step.

  • Claude Code — install the plugin, then launch a session with Channels. Claude Code tutorial
  • Codex — the CLI attaches on its own; Codex Desktop needs the companion launcher. Codex tutorial
  • Grok Bot — a routine webhook in, commands out. Grok Bot tutorial

Connected means the integration's files are in place. A live session is what puts a row on the deck.

5 · Say something

  1. On the deck, press CANCEL to reach Agents. LEFT / RIGHT changes project, the wheel moves the highlight, ENTER opens the session.
  2. Hold PTT, say “Summarize this project and tell me what to do next”, then release. The recording goes to the session open on your Mac.
  3. Read the reply on the deck. When the agent asks a question, ENTER opens the card, the wheel chooses, ENTER answers.

When it doesn’t work

The service is not running
Service → Start. On macOS, allow it in Login Items when the row says it is waiting. If Start does nothing, the copy of the app is not the installed one.
No sessions on the deck
An integration must be set up and a session must be open. Codex is not running means no live local session yet.
No voice input
Check the selected session, the link, and the speech engine under Voice. Use Test Voice. There is no fallback to the Mac's microphone.
The deck says offline
Check the cable or the pairing, then Service → Restart. Demo data is not a live connection.
The screen is locked
Press a key or touch the screen, then turn the wheel counterclockwise four ticks. Those ticks unlock it and do not move the selection.
The service is registered but will not start
macOS found the background item but could not resolve Contents/MacOS/deckd to the app bundle, and launchd gives up with exit 78. Open the app once from Finder, or refresh the bundle index with lsregister -f on the installed copy, then press Start again. macOS retries by itself too, and a launch that succeeds later still leaves last exit code = 78 behind: read state and pid, not that number.

How this page was checked

The app's own wording and the screenshots come from 0.17.0 installed on a Mac. The screenshots are rendered by the app's built-in synthetic mode, which never touches the running service. No deck was attached while this page was written, so the linking steps were not run end to end; on Linux the service unit was confirmed installed and enabled, with both udev rules in place. The Windows steps follow the 0.17.0 package and the Windows guide.
