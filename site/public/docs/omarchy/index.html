OpenWalkieTalkie on Omarchy

The deck as a remote for an Omarchy (Hyprland) laptop

On Omarchy the deck drives your desktop and your coding agents, with no Mac involved. Two small services run on the laptop: deckd, the same service the Mac app runs, built for Linux, and the Omarchy bridge, which connects it to Hyprland and to your Claude Code, Codex and Kimi Code sessions.

  • The Omarchy face: your workspaces and windows. The wheel switches windows, LEFT / RIGHT switch workspaces, ENTER toggles fullscreen and SHIFT+CANCEL the scratchpad.
  • Your sessions on the roster as working, ready or asking. Selecting one brings its terminal to the front.
  • Voice orders: hold PTT on a session and speak. The words are typed into its terminal, and the reply is shown and spoken when the turn ends.
  • The Macropad, System and Usage faces, filled from this laptop.
  • The companion app, the same window as on a Mac, in Omarchy’s app launcher.

There is no Linux download yet: you build deckd and the app from the source, which takes about ten minutes the first time. Every command below runs in a terminal on the Omarchy laptop.

1. Install the tools

sudo pacman -S --needed base-devel git rustup cmake clang espeak-ng wtype
rustup default stable

cmake and clang build the local speech recogniser, espeak-ng speaks replies on the deck, and wtype types orders into terminals. The other libraries the build needs (udev, ALSA, D-Bus) come with Omarchy.

2. Build and install

git clone https://github.com/conol-ai/openwalkietalkie.git
cd openwalkietalkie/host
cargo build --release --target x86_64-unknown-linux-gnu -p deckd -p openwalkietalkie-app
sh omarchy/install.sh target/x86_64-unknown-linux-gnu/release/deckd target/x86_64-unknown-linux-gnu/release/openwalkietalkie-app

install.sh puts deckd and the app in ~/.local/bin, adds the app to Omarchy’s launcher as OpenWalkieTalkie, copies the bridge to ~/.local/share/openwalkietalkie/omarchy, and starts both as systemd user services, deckd and omarchy-deck. They start again at every login. At the end it prints the steps that need root, which are the next section.

3. Let the service open the deck

The deck’s HID device belongs to root until a udev rule hands it to you. Run the two commands install.sh printed:

sudo install -m 644 omarchy/70-openwalkietalkie.rules /etc/udev/rules.d/
sudo udevadm control --reload && sudo udevadm trigger --subsystem-match=hidraw

The rule matches the deck over USB-C and over Bluetooth alike.

4. Connect the deck

  • USB-C: plug it in. Nothing else is needed.
  • Bluetooth: pair OpenWalkieTalkie from Omarchy’s Bluetooth menu (or with bluetoothctl). The deck keeps one pairing at a time: if it was paired with a Mac, remove it there first.

The service links by itself, within seconds. Check it:

deckd status

The link: line should say Connected, session Live.

5. Put your sessions on the deck

Install the hooks for the agents you use. Each install backs up the agent’s settings file first, and adds to it rather than replacing it:

python3 omarchy/omarchy_hook.py install claude
python3 omarchy/omarchy_hook.py install codex
python3 omarchy/omarchy_hook.py install kimi

Sessions that were already open load no new hooks: start them again, and they appear on the Agents face.

6. Voice

Hold PTT on a selected session, speak, and release. The text is typed into that session’s terminal, followed by Enter.

  • With Superwhisper (Omarchy’s dictation, if you use it), there is nothing to set up. It recognises the presses in its own mode, language and vocabulary, in under a second in its Cloud mode. Check that it is ready with superwhisper status.
  • Without it, download the local Whisper model once (about 465 MB): 
    printf '[voice.stt]\nengine = "whisper"\nmodel = "small"\nlanguage = "auto"\n' >> ~/.local/share/openwalkietalkie/config.toml
deckd stt install --model small
    Whisper runs on the laptop’s CPU, so a press takes a few seconds or more, depending on the processor.

Voice reaches sessions that run in a terminal window. A session hosted inside another app has no terminal to type into, and the deck shows the order as not delivered.

7. Optional: Macropad shortcuts

A Macropad key with a keystroke types it on the laptop. To have keys trigger Omarchy’s own shortcuts (Super+…) as well as the focused app’s, the bridge needs to act as a keyboard, which needs /dev/uinput:

sudo install -m 644 omarchy/71-openwalkietalkie-uinput.rules /etc/udev/rules.d/
echo uinput | sudo tee /etc/modules-load.d/openwalkietalkie-uinput.conf
sudo udevadm control --reload && sudo modprobe uinput
systemctl --user restart omarchy-deck

Any program you run can then create an input device, as with ydotool. Without this step, Macropad keys still reach the focused app, but not Omarchy’s shortcuts.

8. Optional: Claude usage bars

The Usage face can show your Claude rate-limit windows, read every five minutes with your Claude Code login:

deckd config set 'usage.providers=["codex","claude"]'

Check the setup

deckd care checks
python3 omarchy/omarchy_hook.py status
journalctl --user -u deckd -u omarchy-deck -f

Or open OpenWalkieTalkie from the app launcher: its Deck page shows the link, and its Service page starts and stops the service (the deckd systemd unit) and opens the app at login. The service keeps all its files in ~/.local/share/openwalkietalkie.

Update

cd openwalkietalkie/host
git pull
cargo build --release --target x86_64-unknown-linux-gnu -p deckd -p openwalkietalkie-app
sh omarchy/install.sh target/x86_64-unknown-linux-gnu/release/deckd target/x86_64-unknown-linux-gnu/release/openwalkietalkie-app

Running install.sh again restarts both services with the new code; quit and reopen the app to run its new version. To update the deck’s firmware, connect it with USB-C and run deckd firmware check, then deckd firmware install, or use the app’s Service page. The deck asks you to press ENTER before it installs. This is the same USB path the Mac uses, but it has not yet been tried on Omarchy.

Not on Omarchy yet

  • Answering permission prompts on the deck: they stay in the terminal.
  • Codex’s usage bars, and the Reader’s history and tool rows for Omarchy sessions.
  • A tray icon and automatic app updates: the app is built from source, so update it as above.

Uninstall

python3 omarchy/omarchy_hook.py uninstall all
systemctl --user disable --now deckd omarchy-deck
rm -f ~/.config/systemd/user/deckd.service ~/.config/systemd/user/omarchy-deck.service ~/.local/bin/deckd ~/.local/bin/openwalkietalkie-app
rm -f ~/.local/share/applications/openwalkietalkie.desktop ~/.local/share/icons/hicolor/512x512/apps/openwalkietalkie.png ~/.config/autostart/openwalkietalkie.desktop
rm -rf ~/.local/share/openwalkietalkie
sudo rm -f /etc/udev/rules.d/70-openwalkietalkie.rules /etc/udev/rules.d/71-openwalkietalkie-uinput.rules /etc/modules-load.d/openwalkietalkie-uinput.conf

The hook uninstall removes only what it added to each agent’s settings.

Something not working? Open an issue with the output of deckd care checks and the last lines of journalctl --user -u deckd -u omarchy-deck. The full reference is the Omarchy bridge README.
