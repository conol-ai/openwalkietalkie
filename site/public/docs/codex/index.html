Connect Codex

CLI, Codex Desktop and one local daemon · about ten minutes

There are two ways in, and they are not the same. The Codex CLI reaches the deck on its own. Codex Desktop needs a launcher that puts it on the same local daemon.

What gets connected

The app does not install Codex and does not proxy it. It talks to the local daemon Codex runs, so what the deck shows is the sessions that daemon has.

  • Codex CLI — the shared daemon. No files and no installer; the row is a switch.
  • Codex Desktop — a launcher in ~/Applications that starts or reuses that daemon and points Desktop at its Unix socket. The launcher is macOS only.
  • Hooks fallback — only when the daemon path is not available: a hooks.json written into $CODEX_HOME.

1 · Codex CLI

  1. Start a session the usual way, in the project you want: codex.
  2. The Codex CLI row turns on by itself once a session is running: you get a count and an entry on the deck. On Omarchy it reads Off after installation, because the installer sets codex.daemon=false and the Omarchy bridge registers those sessions itself.

2 · Codex Desktop

  1. Press Set Up on the Codex Desktop row. It writes Codex with OpenWalkieTalkie.app into ~/Applications.
  2. Quit Codex Desktop and ChatGPT completely. The launcher does not interrupt sessions that are already running.
  3. Finder → Go → Go to Folder… → ~/Applications → open Codex with OpenWalkieTalkie.app.

The launcher starts or reuses the local daemon and connects Desktop through its Unix socket. Open Desktop through that launcher every time: the normal app goes back to its own daemon, and the deck then has nothing to read.

3 · What you should see

  • Codex CLI row: Connected while the daemon is reachable; CLI and Desktop threads share its count.
  • Codex Desktop row: Installed only says the launcher files are in place.
  • On the deck: CANCEL → Agents, where Desktop threads sit next to CLI sessions.

When it doesn't work

Codex is not running
The row needs a live daemon. Open a local codex session, or start Desktop through the launcher.
The launcher refuses to start
Quit Codex Desktop / ChatGPT first, then open Codex with OpenWalkieTalkie again. Running sessions are not interrupted automatically. Quit both, then open the launcher again.
Installed, but nothing on the deck
Installed describes files. Desktop has to be started through the launcher for the deck to see it.
The hooks fallback stops firing
A hook's trust is positional and keyed on the real path of hooks.json. After the file or its path changes, Codex reports the hook as modified and it stops firing without notice: grant trust again through the app.

How this page was checked

Labels and paths come from the app and from the background service's source in 0.17.0, including the launcher's own alert text. Neither path was walked end to end on this build: no CLI thread and no Desktop thread were put on a deck while this page was written.

Where next
