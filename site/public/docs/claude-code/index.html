TUTORIAL · CLAUDE CODE · APP 0.17.0

Connect Claude Code

Plugin, Channels and one live session · about ten minutes

The deck talks to a Claude Code session that is already running on your machine. Two things have to be true: the plugin has to be installed in Claude Code, and the session has to be started with Channels on.

What gets connected

Set Up in the app does not install Claude Code. It writes a local plugin marketplace under ~/Library/Application Support/OpenWalkieTalkie/claude-marketplace/ and registers it, so this machine's Claude Code learns that the deck exists.

  • The plugin: hooks that let a session report itself to the background service.
  • Channels: the live channel the app reads to put a session on the deck. Separate row, separate switch.
  • Your projects: not touched. The plugin is installed at user scope, never per project.

Linux

On Linux, the Omarchy bridge puts your Claude Code session on the deck. Claude Code Channels, the two-way message route, is not available in this release; the fix is in the next one. Until then, the steps below apply to macOS and Windows.

1 · Install the plugin

  1. Open Integrations and find Claude Code. If the row says Set Up, press it.
  2. If the row offers Copy Command, run the two commands below in a terminal. Both are idempotent.
  3. A session that was already open when the plugin was installed will not see it. Start a new one, or run /reload-plugins.
claude plugin marketplace add '<marketplace path>' --scope user --json
claude plugin install openwalkietalkie@openwalkietalkie --scope user --json

The row reads Connected once the plugin is registered at user scope. That is a statement about files, not about a running session.

2 · Start a session with Channels

Claude Code does not load Channels unless you ask for them at launch.

claude --dangerously-load-development-channels plugin:openwalkietalkie@openwalkietalkie

The app has this command behind Integrations → Claude Channels → How to Connect… → Copy Command; the path is the same. Claude asks for a confirmation on the first launch: accept it.

3 · What you should see

  • Claude Code row: Connected, plus a session count once a session is open.
  • Claude Channels row: its own state, No session connected until a Channels session runs.
  • On the deck: CANCEL → Agents lists the session. Nothing else on the deck needs configuring.

When it doesn't work

Needs repair
If you just upgraded the app, Needs repair is the expected state: the managed plugin files no longer match what Claude Code recorded. Press Repair once, and the plugin is rewritten and registered again.
No session connected on Claude Channels
The session was not started with the Channels flag, or the confirmation was dismissed. Quit it and start again with the copied command.
Connected, but no entry on the deck
A project's own .claude/settings.json can turn the plugin off for that repository with enabledPlugins["openwalkietalkie@openwalkietalkie"]: false. The app cannot see that switch.
Nothing works right after an update
A plugin is read at session start. A session that was open before the update needs /reload-plugins or a restart.

How this page was checked

Every label and path comes from the app itself and from the background service's source in 0.17.0, and both commands are the ones the app copies. The page was not walked through end to end with a live Claude Code session, so read the order as the one the code assumes, not as a transcript of a run.
