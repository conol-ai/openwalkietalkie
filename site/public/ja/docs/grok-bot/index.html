チュートリアル · GROK BOT · アプリ 0.17.0

Grok Bot を接続する

ルーティン 1 つ、Webhook 1 つ、キー 1 つ · 所要時間は 10 分ほど

Grok Bot はほかの 2 つとは逆です。載せるローカルセッションはありません。Grok Bot でルーティンを作り、このマシンに向ければ、デバイスがそのボットのマイクと画面になります。

何がつながるのか

ボットは、アプリの設定ファイルの 1 行と、システムが預かるキー 1 つでできています。Webhook は Grok Bot 側にあり、アプリは送って返事を読むだけです。

  • ボット — config.toml の [grokbot.bots.<id>] 1 件：名前、Webhook の URL、設定。
  • キー — システムが保管し、そのファイルには入りません。macOS はキーチェーン（service ai.cohdl.openwalkietalkie、account grokbot.bots.<id>.key）、Windows は資格情報マネージャー、Linux や隔離したデータディレクトリでは grokbot-keys.toml になります。
  • ルーティン — Grok Bot 側で作るもので、ここではありません。URL とキーはこれが渡してくれます。

1 · Grok Bot でルーティンを作る

  1. Grok Bot で使いたいボットを開き、Settings → Computer でコマンドの実行を許可します。許可しないと、ルーティンは返事はできても何も実行できません。
  2. ルーティンを作り、チャット上部のボット名 → Details → routine → Webhook を開きます。POST to の URL とキーが出ます。

2 · ここにボットを追加する

  1. 連携 → Grok Bot → ボット… → 追加 を開きます。
  2. デバイスに出したい名前を付け、POST to の URL とキーを貼って、追加 を押します。
  3. テスト を押します。Webhook に 1 回リクエストを送り、ルーティンが受け付けたかを返します。

その行にプロンプトをコピーがある場合、それは同じルーティンを Grok Bot 自身の言葉で書いたものです。ボットのチャットに送れば、Grok Bot がルーティンを作ってくれます。どちらでも最後は URL とキーが 1 つずつ残ります。

3 · 何が見えるはずか

  • Grok Bot の行：設定済み とボットの数。最初の 1 つを入れるまでは 未設定。
  • キーがありません は、設定にボットがあるのにシステムにキーがない状態です。ルーティンの現在のキーでもう一度追加します。
  • デバイス側：CANCEL → Agents にボットが名前で並びます。どこかでチャットを開いておく必要はありません。

うまくいかないとき

Grok Bot がキーを拒否しました（HTTP 401）
ルーティンを作り直したか、キーが入れ替わっています。ルーティンのキーをもう一度コピーして、ボットを追加し直します。HTTP 403 も同じ扱いです。
Grok Bot はこの Webhook を認識していません（HTTP 404）
その URL のルーティンはもう存在しません。ルーティンの POST to の URL をもう一度コピーして、ボットを追加し直します。
キーがありません
設定にボットがあり、システムにキーがありません。もう一度追加します。同じボットを追加し直すと、新しいキーを渡さない限り元のキーが使われます。
ボットは返事をするが、コンピュータを使えない
Grok Bot の Settings → Computer で許可されていません。ルーティンは動き、デバイスにも言葉は出ますが、何も実行されません。
Grok Bot は実行を開始しませんでした
キーは受け付けられましたが、この実行は始まっていません。一時停止中のルーティンがこうなります。アプリは 「ルーティンが一時停止していませんか？」 と尋ねるので、Grok Bot で再開してから、もう一度 テスト を押します。

このページの確認方法

行の状態とエラー文はアプリと 0.17.0 のサービスのソースから、保存場所はサービス自身のドキュメントから取っています。このページは実際の Grok Bot ルーティンに対して実行していません。上の HTTP の答えはアプリ側の文字列で、生きたルーティンの観察ではありません。
