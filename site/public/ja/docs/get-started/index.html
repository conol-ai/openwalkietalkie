はじめかた

macOS・Windows・Linux · 所要時間は 10 分ほど

アプリを入れて、デバイスをつないで、コーディングエージェントを 1 つ接続します。3 ステップで、デバイスは既に開いているセッションの 2 台目の画面になります。

用意するもの

  • 充電のあるデバイス。
  • macOS 13 以降の Mac、Windows の PC、または Linux（サポートしている構成は Omarchy）。
  • USB-C のデータケーブル。給電専用のケーブルでは何もつながりません。
  • インストールしてサインイン済みのコーディングエージェントが 1 つ：Claude Code、Codex、Grok Bot。

1 · アプリを入れる

macOS

  1. ダウンロード欄からチップに合うディスクイメージを入手し、開いて OpenWalkieTalkie を アプリケーション にドラッグします。
  2. ディスクイメージからではなく「アプリケーション」から起動します。イメージから実行した複製は macOS に隔離され、バックグラウンドサービスを登録できません。

Windows

  1. リリースページから OpenWalkieTalkie-0.17.0-windows-x86_64.zip をダウンロードし、残しておくフォルダに展開します。
  2. このビルドは署名されていません。SmartScreen が Windows によって PC が保護されました と表示します。詳細情報 を選び、実行 を選びます。

Windows ガイド はプレビュー版、トレイアイコン、USB-C 経由のファームウェア更新を扱っています。

Linux

サポートしている構成は Omarchy です。サービスとアプリをビルドしてインストールし、デバイスと仮想キーボードの udev ルールを 2 本読み込みます。コマンドは Omarchy ガイド にあります。このページは手順のどこに位置するかだけを示します。

2 · デバイスをつなぐ

  1. まず有線。USB-C データケーブルをつなぎ、macOS に尋ねられたらアクセサリを許可します。PTT を 2 秒押して電源を入れます。
  2. 無線。Bluetooth で OpenWalkieTalkie をペアリングし、プライバシーとセキュリティ → Bluetooth でコンパニオンアプリを許可します。
  3. 確認。デバイス → お使いのデバイス → 接続 を開きます。ケーブル または Bluetooth の緑の点が出ていれば、サービスから見えています。

3 · バックグラウンドサービスを起動する

サービス を開きます。最初のカードがバックグラウンドサービスが動いているかを示し、デバイス上のほかのすべてがこれに依存します。

  • macOS。動いていなければ 開始 を押します。行に承認待ちと出ている場合は「システム設定」を開き、ログイン項目 で許可します。許可するまで起動しません。
  • Windows。サービスは Run キーでサインイン時に起動し、ログイン時に起動 の行がそれを表示・切り替えます。
  • Linux。systemctl --user status deckd。ユニットが無ければ、Omarchy ガイドのインストーラーがまだ走っていません。

ウインドウを閉じる前に ログイン時に起動 をオンにします。サービスが無いデバイスは、オフラインとしか表示されません。

4 · エージェントを 1 つ接続する

まず 1 つで十分です。連携 の各行が 1 つのエージェントに対応します。手順は各チュートリアルにあります。

  • Claude Code — プラグインを入れ、Channels 付きでセッションを起動します。Claude Code チュートリアル
  • Codex — CLI は自動でつながります。Codex Desktop はコンパニオンのランチャーが必要です。Codex チュートリアル
  • Grok Bot — ルーチンの webhook が入り、コマンドが出ていきます。Grok Bot チュートリアル

接続済み は連携のファイルが揃ったという意味です。デバイスに行が出るのは、生きているセッションがあるときです。

5 · 話しかける

  1. デバイスで CANCEL を押して Agents に入ります。LEFT / RIGHT でプロジェクト、ホイールでハイライト、ENTER でセッションを開きます。
  2. PTT を押したまま「このプロジェクトを要約して、次に何をすべきか教えて」と言い、離します。録音は Mac で開いているセッションに送られます。
  3. 返答はデバイスで読みます。エージェントが質問したら ENTER でカードを開き、ホイールで選び、ENTER で答えます。

うまくいかないとき

サービスが動いていない
サービス → 開始。macOS で行が承認待ちなら ログイン項目 で許可します。「開始」を押しても何も起きないなら、使っているのはインストール済みの複製ではありません。
デバイスにセッションが出ない
連携を設定し、かつ セッションを開いている必要があります。Codex が実行されていません は、生きているローカルセッションがまだ無いという意味です。
音声入力が効かない
選択中のセッション、接続、音声 で選んだ音声エンジンを確認します。音声をテスト を使います。Mac のマイクに切り替わることはありません。
デバイスがオフラインと出る
ケーブルかペアリングを確認し、サービス → 再起動。デモデータは実際の接続ではありません。
画面がロックされている
キーを押すか画面に触れ、ホイールを反時計回りに 4 目盛り回します。この 4 目盛りはロックを解くだけで、選択は動きません。
サービスは登録済みなのに起動しない
macOS はバックグラウンド項目を見つけたものの、Contents/MacOS/deckd をアプリバンドルに解決できず、launchd は終了コード 78 で諦めます。Finder でアプリを一度開くか、インストール済みの複製に対して lsregister -f を実行してバンドル索引を更新してから、もう一度「開始」を押します。macOS 自身も再試行します。後から起動に成功しても last exit code = 78 は残るので、見るのは state と pid です。

このページの確認方法

本ページの UI 文言とスクリーンショットは、Mac にインストールした 0.17.0 から取っています。スクリーンショットはアプリ内蔵の合成レンダリングモードで生成したもので、稼働中のサービスには触れません。執筆時点で実機を接続していないため、デバイス接続の手順は端から端まで実行していません。Linux ではサービスのユニットがインストール済みで有効なこと、2 本の udev ルールが配置済みであることを確認しました。Windows の手順は 0.17.0 のパッケージと Windows ガイドに基づいています。
