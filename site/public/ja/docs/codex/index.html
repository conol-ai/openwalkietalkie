チュートリアル · CODEX · アプリ 0.17.0

Codex を接続する

CLI、Codex Desktop、1 つのローカルデーモン · 所要時間は 10 分ほど

入り口は 2 つあり、同じではありません。Codex CLI は自分でデバイスに届きます。Codex Desktop は、同じローカルデーモンに載せるためのランチャーが要ります。

何がつながるのか

アプリは Codex をインストールせず、代理もしません。Codex が動かしているローカルデーモンと話すので、デバイスに出るのはそのデーモンが持っているセッションです。

  • Codex CLI — 共有デーモン。ファイルもインストーラーも不要で、行はスイッチだけです。
  • Codex Desktop — ~/Applications に置くランチャー。そのデーモンを起動または再利用し、Desktop をその Unix ソケットに向けます。 このランチャーは macOS 専用です。
  • hooks フォールバック — デーモンの経路が使えないときだけ：$CODEX_HOME に hooks.json を書きます。

1 · Codex CLI

  1. いつものように、使いたいプロジェクトでセッションを開始します：codex。
  2. セッションが動き始めると、Codex CLI の行は自動でオンになります。数が表示され、デバイスにも項目が出ます。Omarchy ではインストール後に「オフ」と表示されます。インストーラーが codex.daemon=false を設定し、Omarchy ブリッジがセッションを登録するためです。

2 · Codex Desktop

  1. Codex Desktop の行で 設定する を押します。Codex with OpenWalkieTalkie.app が ~/Applications に書き込まれます。
  2. Codex Desktop と ChatGPT を完全に終了します。ランチャーは実行中のセッションを中断しません。
  3. Finder → 移動 → フォルダへ移動… → ~/Applications → Codex with OpenWalkieTalkie.app を開きます。

ランチャーはローカルデーモンを起動または再利用し、Unix ソケット経由で Desktop をつなぎます。以後 Desktop は必ずこのランチャーから開いてください。通常のアイコンから開くと自分のデーモンに戻り、デバイス側は何も読めなくなります。

3 · 何が見えるはずか

  • Codex CLI の行：デーモンに届く間は接続済み。CLI と Desktop のスレッドはこの数を共有します。
  • Codex Desktop の行：インストール済み はランチャーのファイルがあるというだけです。
  • デバイス側：CANCEL → Agents。Desktop のスレッドは CLI のセッションの隣に並びます。

うまくいかないとき

Codex が動いていない
この行には生きたデーモンが要ります。ローカルで codex のセッションを開くか、ランチャーから Desktop を起動します。
ランチャーが起動を拒む
Quit Codex Desktop / ChatGPT first, then open Codex with OpenWalkieTalkie again. Running sessions are not interrupted automatically. 両方終了してから、もう一度ランチャーを開きます。
インストール済みなのにデバイスに出ない
インストール済み はファイルの話です。デバイスから見えるには、Desktop をランチャー経由で起動する必要があります。
hooks フォールバックが動かなくなる
フックの信頼は位置、つまり hooks.json の実パスに紐づきます。ファイルかパスが変わると Codex は modified と見なし、通知なく止まります。アプリから信頼をやり直してください。

このページの確認方法

ラベルとパスはアプリと 0.17.0 のバックグラウンドサービスのソースから取り、ランチャー自身の警告文も原文です。どちらの経路もこのビルドでは端から端まで実行していません。このページを書いている間、CLI のスレッドも Desktop のスレッドもデバイスには載せていません。
