OpenWalkieTalkie v0.16.0：ウィンドウがわかる口述

2026年11月22日試験的な口述とモデルへの接続

0.16.0 で加わった機能は 1 つだけで、しかも試験的です。カーソル位置への口述を、入力先のウィンドウに合わせて書き直せます。オンにするまではオフのままです。デバイスのファームウェアは 0.14.0 のまま変わりません。

何が問題だったか

話した言葉は普通の文章として出てきます。ターミナルの上で PTT を押して「system CTL status」と話すと、入力されるのは systemctl status ではなく「System CTL status」という言葉です。何を意図したかは言葉の行き先しだいなのに、口述はそれを知りませんでした。

何をするか

この機能をオンにすると、カーソル位置への口述（Omarchy の Dictate 項目）は、入力される前に書き直されます。ウィンドウ判別モデルは、フォーカス中のウィンドウのアプリ名とタイトルを、テキストとしてだけ読みます。スクリーンショットもウィンドウの中身も読みません。そこがどんな場所か、つまりシェル、エージェント、エディター、チャット、文章のどれかを判断します。続いて書き直しのモデルが、その場所に合わせて言葉を書き直します。ウィンドウ判別モデルがない場合は、組み込みのルールがアプリ名から判断します。

口述した言葉は書き直しのモデルのプロバイダーに、アプリ名とタイトルはウィンドウ判別モデルのプロバイダーに送られます。サービスのログに残るのは口述ごとの結果、長さ、所要時間だけで、言葉は残りません。オンにして 2 つのモデルを選ぶのは、コンパニオンアプリの音声 › ウィンドウに合わせた口述の書き直しです。

3 秒を過ぎたら、聞き取ったとおりに

クラウドのモデルを使う口述では、2 つの呼び出しを合わせて 3 秒です。モデルがそれより遅い、失敗する、あるいは書き直しに見えない答えを返した場合は、聞き取ったとおりの言葉が入力されます。このパソコンや自分のネットワーク上のモデルにはもっと長い時間を与え、既定で 15 秒、最大 60 秒です。選択画面ではそのモデルにローカル · 遅めと表示されます。動いていないとわかっているローカルのモデルは待ちません。

モデルへの接続

モデルは、音声の下の新しいページモデルへの接続から選びます。プロバイダーの一覧が 1 つあり、プロバイダーごとにキーが 1 つです。キーは OS のキーの保管場所に保存し、config.toml には書きません。ページでは、キーは最後の 4 文字だけを表示します。プロバイダーが使うプロトコルは 2 つのうちどちらかです。OpenAI 互換の chat completions（OpenAI、OpenRouter、Ollama、または指定したアドレスの互換サーバー）か、Anthropic の Messages API です。ElevenLabs はクラウドの音声専用として載っています。Omarchy では、独自のローカルモデルが自動的に見つかります。

試験的である理由

まだ確かめられていないことが 3 つあります。このリリースまで、macOS と Windows の部分は一度もビルドされていませんでした。0.16.0 では CI が両方のシステムでビルドしてテストしましたが、実際のウィンドウを読んだのは Hyprland のウィンドウ読み取りだけです。自分のパソコンで動くモデルはまだ使っておらず、その代役しか使っていません。Anthropic の API も代役に対して試しただけで、本物のサービスでは試していません。デバイスでの実際の口述が、このコードで最初から最後まで正しく書き直されることはまだ確認できていません。また macOS と Windows にはまだ Dictate 項目がないため、そこではこの機能に書き直すものがありません。

更新

Mac ではアップデートを確認…を選ぶか、署名・公証済みの 0.16.0 のアプリ（Apple シリコン用または Intel 用、macOS 13 以降）をインストールします。Windows では、リリースから ZIP をダウンロードします。Omarchy では、Omarchy のガイドのとおりに、最新のコードを取得してサービスとアプリをビルドし、両方で install.sh を実行します。このリリースではデバイスのファームウェアの更新は不要です。
