教學 · CLAUDE CODE · 應用程式 0.17.0

連接 Claude Code

外掛、Channels 與一個活工作階段 · 約十分鐘

裝置對話的是你機器上已經在跑的 Claude Code 工作階段。兩件事必須成立：外掛裝進了 Claude Code，工作階段是用 Channels 啟動的。

連接的是什麼

應用程式裡的「設定」並不安裝 Claude Code。它寫一份本機外掛市集目錄到 ~/Library/Application Support/OpenWalkieTalkie/claude-marketplace/ 並把它登記進去，讓這台機器的 Claude Code 知道裝置的存在。

  • 外掛：一組 hook，讓工作階段能把自己回報給背景服務。
  • Channels：應用程式讀取的即時通道，工作階段就是靠它出現在裝置上。單獨一列，單獨開關。
  • 你的專案：不動。外掛裝在使用者層級，不按專案裝。

Linux

在 Linux 上，Omarchy 橋接會把你的 Claude Code 工作階段送到裝置上。Claude Code Channels 是雙向訊息通道，本版本暫無法使用，下個版本會修復。在此之前，下列步驟適用於 macOS 和 Windows。

1 · 安裝外掛

  1. 開啟 整合，找到 Claude Code。如果那一列寫著 設定，按它。
  2. 如果那一列給了 複製指令，把下面兩條指令在終端機裡跑一遍。兩條都可以重複執行。
  3. 外掛裝好之前就已經開著的工作階段，看不到它。新開一個，或在裡面執行 /reload-plugins。
claude plugin marketplace add '<marketplace path>' --scope user --json
claude plugin install openwalkietalkie@openwalkietalkie --scope user --json

外掛在使用者層級登記好之後，那一列會顯示 已連接。這句話說的是檔案，不是正在跑的工作階段。

2 · 帶 Channels 啟動工作階段

Claude Code 不會自動載入 Channels，除非你在啟動時指名要它。

claude --dangerously-load-development-channels plugin:openwalkietalkie@openwalkietalkie

應用程式裡這條指令在 整合 → Claude Channels → 如何連線… → 複製指令 後面，路徑一樣。首次啟動 Claude 會要求確認：允許即可。

3 · 應該看到什麼

  • Claude Code 列：已連接；工作階段開起來後，還會帶一個工作階段數。
  • Claude Channels 列：自己的狀態，Channels 工作階段沒跑起來之前是沒有工作階段連接。
  • 裝置上：按 CANCEL 進入 Agents，工作階段就列在那裡。裝置上不需要再設定別的。

出問題的時候

需要修復
剛升級應用程式時，顯示需要修復是正常的。受管的外掛檔案與 Claude Code 的記錄不再一致。按一次修復，應用程式就會重寫外掛並重新登記。
Claude Channels 上沒有工作階段連接
工作階段不是用 Channels 參數起的，或者確認被取消了。關掉重開，用複製來的那條指令。
顯示已連接，但裝置上沒有項目
專案自己的 .claude/settings.json 可以用 enabledPlugins["openwalkietalkie@openwalkietalkie"]: false 把這個專案的外掛關掉。應用程式看不到這個開關。
更新之後就不靈了
外掛是在工作階段啟動時讀的。更新前就開著的工作階段，需要 /reload-plugins 或重新啟動。

這一頁是怎麼核對的

所有標籤與路徑都取自應用程式本身與 0.17.0 的背景服務原始碼，兩條指令就是應用程式複製給你的那兩條。這一頁沒有用活的 Claude Code 工作階段端到端跑過，所以請把順序當作程式碼假設的順序，而不是一次實跑的紀錄。
