連接 Grok Bot

一個 routine、一個 webhook、一把金鑰 · 約十分鐘

Grok Bot 跟前兩個反過來：沒有本機工作階段可以掛。你在 Grok Bot 裡建一個 routine，把它指向這台機器，裝置就成了那個機器人的麥克風和螢幕。

連接的是什麼

一個機器人 = 應用程式設定檔裡的一列 + 系統替它保管的一把金鑰。webhook 在 Grok Bot 那邊；應用程式只負責送過去、讀回來。

  • 機器人 —— config.toml 裡的一條 [grokbot.bots.<id>]：名字、webhook 位址和設定。
  • 金鑰 —— 由系統保管，不在那個檔案裡：macOS 進鑰匙圈（service ai.cohdl.openwalkietalkie，account grokbot.bots.<id>.key），Windows 進認證管理員，Linux 或隔離的資料目錄才落到 grokbot-keys.toml。
  • routine —— 在 Grok Bot 裡建，不在這裡。位址和金鑰都是它給的。

1 · 在 Grok Bot 裡建 routine

  1. 在 Grok Bot 裡開啟你要的那個機器人，進 Settings → Computer，允許它執行指令：不允許的話，routine 能回話，但什麼都做不了。
  2. 建一個 routine，然後在聊天頂端點機器人的名字 → Details → routine → Webhook。那裡會給出一個 POST to 位址和一把 金鑰。

2 · 在這裡新增機器人

  1. 開啟 整合 → Grok Bot → 機器人… → 新增。
  2. 取一個你希望顯示在裝置上的名字，貼上 POST to 位址和 金鑰，按 新增。
  3. 按 測試：它會給 webhook 送一個請求，並告訴你 routine 有沒有接受。

如果那一列給了 複製提示詞，那段話是用 Grok Bot 自己的說法描述同一個 routine：送到機器人的聊天裡，Grok Bot 會替你把 routine 建好。兩種做法最後都是拿到一個位址和一把金鑰。

3 · 應該看到什麼

  • Grok Bot 列：已設定，帶機器人數量；第一個加進來之前是 未設定。
  • 缺少金鑰 表示設定裡有這個機器人，但系統裡沒有它的金鑰：拿 routine 目前的金鑰再加一次。
  • 裝置上：CANCEL → Agents 會按名字列出這個機器人，哪裡都不用開著聊天。

出問題的時候

Grok Bot 拒絕了金鑰（HTTP 401）
routine 重建過，或者金鑰輪換了。重新複製 routine 的金鑰，再加一次機器人。HTTP 403 也是同一個處理。
Grok Bot 不認得這個 Webhook（HTTP 404）
這個位址指向的 routine 已經不存在了。重新複製 routine 的 POST to 位址，再加一次機器人。
缺少金鑰
設定裡有這個機器人，系統裡沒有它的金鑰。再加一次：同一個機器人重複新增會沿用原來的金鑰，除非你給了新的。
機器人會回話，但用不了電腦
Grok Bot 的 Settings → Computer 沒允許。routine 照舊跑，裝置照舊顯示出字，但什麼都不會執行。
Grok Bot 沒有開始執行
金鑰被接受了，但這一次執行沒有起來。暫停中的 routine 就是這樣——應用程式會問 「例行任務是否已暫停？」——所以去 Grok Bot 裡恢復它，回來再按 測試。

這一頁是怎麼核對的

各列狀態和錯誤原文取自應用程式與 0.17.0 的服務原始碼，存放位置取自服務自己的文件。這一頁沒有對著真實 Grok Bot routine 跑過：上面那些 HTTP 回答是應用程式自己的字串，不是對活 routine 的觀察。
