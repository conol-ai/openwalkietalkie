入門指南 · 應用程式 0.17.0

入門指南

macOS、Windows 與 Linux · 約十分鐘

裝好應用程式、連上裝置、接通一個程式設計 agent。三步之後，裝置就是你已開啟工作階段的第二塊螢幕。

你需要準備

  • 一台有電的裝置。
  • 一台 macOS 13 或更新版本的 Mac、一台 Windows 電腦，或 Linux（受支援的配置是 Omarchy）。
  • 一條 USB-C 資料線。只供電的線連不上任何東西。
  • 一個已安裝並登入的程式設計 agent：Claude Code、Codex 或 Grok Bot。

1 · 安裝應用程式

macOS

  1. 從下載區依你的晶片下載磁碟映像檔，開啟後把 OpenWalkieTalkie 拖進 應用程式。
  2. 從「應用程式」啟動，不要從磁碟映像檔啟動。從映像檔執行的副本會被 macOS 隔離，無法註冊背景服務。

Windows

  1. 從發佈頁下載 OpenWalkieTalkie-0.17.0-windows-x86_64.zip，解壓縮到一個你會長期保留的資料夾。
  2. 這個建置沒有簽章：SmartScreen 會顯示 Windows 已保護您的電腦。選更多資訊，再選仍要執行。

Windows 指南說明預覽版、系統匣圖示，以及透過 USB-C 更新韌體。

Linux

受支援的配置是 Omarchy。編譯並安裝服務與應用程式，再載入裝置與虛擬鍵盤的兩條 udev 規則。Omarchy 指南裡有指令，照那一頁做：本頁只說它排在流程的哪一步。

2 · 連接裝置

  1. 先接線。接上 USB-C 資料線，macOS 詢問時允許該配件。按住 PTT 兩秒開機。
  2. 無線連線。在藍牙裡配對 OpenWalkieTalkie，並在隱私權與安全性 → 藍牙裡允許這個隨附應用程式。
  3. 確認連線。開啟 裝置 → 你的裝置 → 連線。出現帶 連接線 或 藍牙 的綠點，代表服務看得到它。

3 · 啟動背景服務

開啟 服務。第一張卡片說明背景服務是否正在執行；裝置上其餘的一切都依賴它。

  • macOS。沒在執行就按 啟動。如果那一列說在等待核准，就開啟「系統設定」，在登入項目裡允許它：不核准它不會啟動。
  • Windows。服務透過 Run 機碼在登入時啟動，登入時啟動 這一列會顯示並控制它。
  • Linux。systemctl --user status deckd。如果沒有這個 unit，代表 Omarchy 指南裡的安裝指令碼還沒跑過。

關視窗之前把 登入時啟動 開啟。沒有服務的裝置，只會顯示離線。

4 · 接通一個 agent

先接一個就夠。整合 頁每一列對應一個 agent，具體步驟見各篇教學。

  • Claude Code —— 安裝外掛，再帶 Channels 啟動工作階段。Claude Code 教學
  • Codex —— CLI 自己會接上；Codex Desktop 需要隨附的啟動器。Codex 教學
  • Grok Bot —— 一個 routine 的 webhook 進來，指令出去。Grok Bot 教學

已連接 指整合的檔案已經就位。真正讓一列出現在裝置上的，是活著的工作階段。

5 · 說一句話

  1. 在裝置上按 CANCEL 進入 Agents。LEFT / RIGHT 換專案，滾輪移動醒目提示，ENTER 開啟工作階段。
  2. 按住 PTT，說「總結一下這個專案，告訴我下一步要做什麼」，然後放開。錄音會送到你 Mac 上開啟的那個工作階段。
  3. 在裝置上讀回覆。agent 提問時，按 ENTER 開啟卡片，滾輪選擇，ENTER 作答。

出問題的時候

服務沒在執行
服務 → 啟動。macOS 上如果那一列說在等待，就到登入項目裡允許。按了「啟動」沒有反應，代表用的不是安裝好的那份副本。
裝置上沒有工作階段
整合要設定好，並且要有一個開啟的工作階段。Codex 未執行 表示還沒有活著的本地工作階段。
語音輸入沒反應
先看選取的工作階段、連線狀態，以及 語音 裡選的語音引擎。用 測試語音。它不會退回使用 Mac 的麥克風。
裝置顯示離線
檢查連接線或配對，然後 服務 → 重新啟動。示範資料不是真實連線。
螢幕鎖住了
按任意鍵或觸碰螢幕，然後把滾輪逆時針轉四格。這四格只解鎖，不會移動選取項目。
服務已註冊，但起不來
macOS 找到了背景項目，卻沒把 Contents/MacOS/deckd 解析到應用程式包裡，launchd 以結束碼 78 放棄。先用 Finder 開啟一次應用程式，或對已安裝的副本跑一次 lsregister -f 刷新 bundle 索引，再按「啟動」。系統自己也會重試；之後啟動成功，last exit code = 78 仍會留著：看 state 和 pid，別看這個數字。

這一頁是怎麼核對的

本頁引用的介面文字與截圖都取自安裝在 Mac 上的 0.17.0。截圖由應用程式內建的合成渲染模式產生，不會碰觸正在執行的服務。撰寫本頁時沒有接上實機，因此連接裝置的相關步驟並未端到端執行；Linux 方面確認了服務單元已安裝並啟用、兩條 udev 規則已就位。Windows 的步驟依 0.17.0 安裝包與 Windows 指南整理。
