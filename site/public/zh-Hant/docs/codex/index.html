連接 Codex

CLI、Codex Desktop 與一個本機 daemon · 約十分鐘

有兩條路，而且它們不一樣。Codex CLI 自己就能接到裝置上；Codex Desktop 需要一個啟動器，把它放到同一個本機 daemon 上。

連接的是什麼

應用程式不安裝 Codex，也不代理它。它對話的是 Codex 跑的那個本機 daemon，所以裝置上顯示的就是那個 daemon 手裡的工作階段。

  • Codex CLI —— 共用 daemon。不用寫檔案，也沒有安裝程式；那一列就是個開關。
  • Codex Desktop —— ~/Applications 裡的一個啟動器，負責拉起或重用那個 daemon，並把 Desktop 指到它的 Unix socket 上。 這個啟動器僅適用於 macOS。
  • hooks 備援 —— 只在 daemon 這條路走不通時才用：往 $CODEX_HOME 裡寫一份 hooks.json。

1 · Codex CLI

  1. 照平常的方式，在你要的專案裡開工作階段：codex。
  2. 工作階段執行後，Codex CLI 那一列會自動開啟，顯示工作階段數，裝置上也會出現項目。在 Omarchy 上，安裝後這一列顯示「關閉」，因為安裝指令碼設定了 codex.daemon=false，由 Omarchy 橋接登記這些工作階段。

2 · Codex Desktop

  1. 在 Codex Desktop 那一列按 設定。它會把 Codex with OpenWalkieTalkie.app 寫進 ~/Applications。
  2. 把 Codex Desktop 和 ChatGPT 完全結束。啟動器不會打斷已經在跑的工作階段。
  3. Finder → 前往 → 前往檔案夾… → ~/Applications → 開啟 Codex with OpenWalkieTalkie.app。

啟動器會拉起或重用本機 daemon，並透過它的 Unix socket 把 Desktop 接上。以後每次都從這個啟動器開啟 Desktop：從正常圖示開啟，它就回到自己的 daemon，裝置上就讀不到東西了。

3 · 應該看到什麼

  • Codex CLI 列：daemon 能連上時顯示已連接；CLI 與 Desktop 的執行緒共用這個計數。
  • Codex Desktop 列：已安裝 只說明啟動器檔案就位了。
  • 裝置上：CANCEL → Agents，Desktop 的執行緒就排在 CLI 工作階段旁邊。

出問題的時候

Codex 沒在執行
這一列需要一個活著的 daemon。開一個本機 codex 工作階段，或從啟動器啟動 Desktop。
啟動器不讓啟動
Quit Codex Desktop / ChatGPT first, then open Codex with OpenWalkieTalkie again. Running sessions are not interrupted automatically. 把兩個都結束掉，再開一次啟動器。
顯示已安裝，但裝置上什麼都沒有
已安裝 說的是檔案。Desktop 必須從啟動器起，裝置才看得到。
hooks 備援不響了
hook 的信任是按位置、按 hooks.json 的真實路徑算的。檔案或路徑一變，Codex 就把它當成 modified，然後靜默失效：回到應用程式裡重新授予信任。

這一頁是怎麼核對的

標籤與路徑取自應用程式與 0.17.0 的背景服務原始碼，啟動器自己那句提示也是原文。兩條路都沒有在這個建置上端到端跑過：寫這一頁時，沒有任何 CLI 執行緒或 Desktop 執行緒真的上過裝置。
