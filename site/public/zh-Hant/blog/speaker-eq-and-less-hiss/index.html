OpenWalkieTalkie v0.7.0：語音更清楚，底噪更少

2026年10月20日應用程式與韌體更新

0.7.0 版著重在裝置的聲音。Mac 上的服務現在會對語音與提示音套用固定的揚聲器等化，Rev A 也重新從 RAM 執行程式碼與字型資源，以減少與快閃記憶體存取相關的底噪。

音訊到達揚聲器之前先做等化

服務在透過 USB 或低功耗藍牙傳送之前，會先處理混合後的語音與提示音。預設把 250 Hz 高通濾波器，與 1.1 kHz 衰減 5 dB、6.3 kHz 衰減 6 dB 結合起來。它保留 3 dB 的餘裕，並把取樣限制在 −1 dBFS。

濾波器狀態在音訊區塊之間與靜音期間保持連續，並在輸出重新開啟時重設。無效的取樣不會影響之後的音訊。

對於自訂的 16 kHz 裝置音訊輸出，這個預設會自動啟用；本版本沒有等化開關。它不會增強揚聲器的低音，也不會補平狹窄的響應凹陷，所以低音較重的內容聽起來可能比較小聲。本機產生的遊戲音效、舊的 CoreAudio 輸出與原始量測音則維持不變。

Rev A 上的快閃記憶體活動更少

Rev A 的程式碼、常數與字型資源會在啟動時複製到 PSRAM，中斷向量則放在 SRAM。啟動時會驗證這些複本，連續三次失敗後回到 USB 復原模式。Rev B 與 LilyGo 仍從 NOR 快閃記憶體執行。

快閃記憶體分割區與兩份藍牙儲存都維持原位，PSRAM 的最後 1 MiB 仍保留給診斷使用。

我們聽到與檢查了什麼

等化與從 RAM 執行的變更，在一塊 Rev A 板上透過 USB 實際測試過。語音播放完整，沒有遺失主機端的音訊影格；操作者回報底噪明顯減少；在一次使用同一等化實作、標示清楚的低音比較中，開啟等化的版本較受青睞。

這些是聽感結果，不是新的校準聲學量測。那次測試沒有測 Rev B 硬體，也沒有只用藍牙聆聽。自動檢查涵蓋各主機板的執行配置、啟動時的複製邊界、向量位置、受保護的快閃記憶體儲存，以及等化是否進入編碼後的裝置音訊串流。

兩邊都要更新

安裝已簽署並經過公證的 Mac 應用程式（Apple Silicon 或 Intel），或使用檢查更新。需要 macOS 13 或更新版本。確認應用程式與服務都顯示 0.7.0，透過 USB-C 連接一台裝置，然後使用服務 → 更新 → 檢查韌體更新。

已使用復原協定 2 的裝置會收到一般的應用程式更新。使用舊開機載入程式的裝置需要沿用現有的引導式遷移：依照應用程式中的電源與 USB 說明操作，並在繼續之前接受它的警告。已有的裝置請使用應用程式的更新功能；全晶片原廠映像檔會覆寫設定與配對資料。
