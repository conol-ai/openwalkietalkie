OpenWalkieTalkie v0.4.0：恢复过程显示在屏幕上，留出成长空间

2026年10月18日应用和固件更新

OpenWalkieTalkie 0.4.0 为设备的功能留出了更多空间，并让固件恢复过程直接显示在设备上。它还加入了中文文字支持，Codex 的提问和回答也更清楚了。

应用程序可用的闪存更多了

16 MiB 的 NOR 闪存现在有 15.75 MiB 可用于应用程序代码和资源。分区表、引导程序和两个蓝牙存储区仍保留各自的空间。中文字体放在应用程序的高位区，为低位区的代码留出更多空间。

时钟配置修正后，固件重新直接从 NOR 闪存执行，启动时不再把整个应用程序复制到 PSRAM。

恢复界面和更快的 USB 更新

新的引导程序会在设备屏幕上显示恢复说明、传输进度、完成状态和错误。已更新的设备可以使用稀疏传输和流水线式 USB 批量传输，跳过对填充区域的写入，并保留蓝牙存储区。

从旧引导程序进行的首次升级，仍然先通过 HID 传输一个临时更新程序。这一阶段需要几分钟。之后的阶段可以使用新的传输方式，但闪存的擦除和写入时间仍会计入总时长。

从 0.3.0 升级

安装 0.4.0 版 Mac 应用，用 USB-C 数据线连接一台设备，然后打开 服务 → 更新 → 检查固件更新。继续之前，请核对主板版本和序列号。

这次升级可能会替换引导程序。在应用报告成功之前，请保持 USB-C 供电，并让 Mac 保持唤醒。替换引导程序时断电，可能导致设备既无法启动也无法通过 USB 恢复，只能进行硬件维修。应用会显示这条警告，并要求你明确确认后才开始迁移。

应用会安装一个临时更新程序，备份并替换引导程序，读回内容以验证写入，然后安装最终固件。请使用这个引导式流程，不要手动刷写 bootstrap 或 recovery 文件。更新程序不会重写分区表，并会跳过蓝牙存储区。

完成后，设备的“关于”页面应显示 0.4.0 · Rev A 或 0.4.0 · Rev B。版本标签现在会自动跟随固件构建。两种主板版本的固件及其经过验证的清单都随应用附带，因此离线也可以更新固件。

中文文字和更清楚的助手对话

内置的 Noto Sans CJK 字体加入了简体和繁体中文的支持。Codex 的澄清提问和回答会以易读的标题、问题背景和回答文字显示，而不再显示其传输封装。这个版本也包含 0.3.0 之后加入的 Codex Desktop 集成和蓝牙信号强度指示。

已经测试的内容

两种主板版本都能构建，并通过了软件检查。更早的 0.3.1 候选版本在 Rev A 上完成了从原版 0.3.0 到新引导程序的完整图形界面迁移，用时约五分半钟，使用的恢复程序来源相同。CI 重新构建的发布版本生成的引导程序字节不同，尚未在该测试中刷写。

0.4.0 最终版的图形界面复测在刷写之前被本地桌面自动化阻断。手头没有已出货的 Rev B，因此它的完整迁移、显示表现以及配对和设置能否保留，仍有待在硬件上检查。这些是待完成的检查，不是已完成的验证。本次没有进行设备音频测试。

获取 v0.4.0

使用 检查更新，或下载已签名并经过公证的 Mac 应用，支持 Apple Silicon 和 Intel。需要 macOS 13 或更高版本。

GitHub 发布版本包含固件、校验和以及中文升级指南。DMG 中也附有同一份指南。
