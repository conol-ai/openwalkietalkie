OpenWalkieTalkie v0.16.0：懂得窗口的口述

2026年11月22日实验性口述功能和模型接入

0.16.0 版只增加了一项功能，而且是实验性的：在光标处口述的内容，可以按它要进入的窗口进行改写。在你打开之前它是关闭的。设备固件不变，仍是 0.14.0。

问题

说出来的话会变成普通文字。在终端上按住 PTT 说“system CTL status”，输入的就是“System CTL status”这几个词，而不是 systemctl status。你想要的是什么，取决于这些词要去哪里，而口述并不知道。

它做什么

打开这项功能后，在光标处的口述（Omarchy 上的 Dictate 条目）会在输入之前先被改写。窗口识别模型读取聚焦窗口的应用名称和标题，只有这两项纯文本，别无其他：从不截图，也从不读取窗口内容。它判断那是什么样的地方：shell、助手、编辑器、聊天，还是普通文字。然后改写模型为那里改写你的话。没有窗口识别模型时，由内置规则根据应用名称来判断。

你口述的话会发给改写模型的服务商，应用名称和标题会发给窗口识别模型的服务商。服务的日志只记录每次口述的结果、长度和耗时，从不记录内容。在配套应用的语音 › 按窗口改写听写中打开这项功能，并选择两个模型。

三秒，否则按原话输入

使用云端模型的口述，两次调用加起来只有 3 秒。如果模型比这慢、出错，或者回答的内容看起来不像改写，就会按你说的原话输入。在这台电脑或你自己网络上的模型会得到更长时间，默认 15 秒，最多 60 秒，选择器会把它标为本地 · 较慢。已知没有运行的本地模型不会被等待。

模型接入

这些模型来自语音下的一个新页面：模型接入。这里是一份服务商列表，每个服务商一个密钥，保存在操作系统的密钥存储中，从不写进 config.toml。页面只显示密钥的最后四个字符。服务商使用两种协议之一：兼容 OpenAI 的 chat completions（OpenAI、OpenRouter、Ollama，或你给出地址的任何兼容服务器），或 Anthropic 的 Messages API。ElevenLabs 只用于云端语音。在 Omarchy 上，它自己的本地模型会被自动发现。

为什么是实验性的

有三件事还没有得到证明。在这个版本之前，macOS 和 Windows 部分从未被构建过；0.16.0 的 CI 在这两个系统上构建并测试了它们，但只有 Hyprland 的窗口读取器读过真实的窗口。还没有用过在你自己电脑上运行的模型，只用过模拟替身。Anthropic 的 API 也只对替身试过，从未对真实服务试过。还没有证明设备上的真实口述能用这套代码从头到尾正确改写，而且 macOS 和 Windows 还没有 Dictate 条目，所以在那里这项功能没有东西可改写。

更新

在 Mac 上，选择检查更新…，或安装已签名并经过公证的 0.16.0 应用（Apple Silicon 或 Intel，macOS 13 或更高版本）。在 Windows 上，从发布页面下载 ZIP。在 Omarchy 上，拉取代码，构建服务和应用，再用这两者运行 install.sh，具体见 Omarchy 指南。这个版本不需要更新设备固件。
