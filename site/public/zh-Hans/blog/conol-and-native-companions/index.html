OpenWalkieTalkie v0.11.0：Conol 与原生配套程序

2026年10月28日应用和固件更新

0.11.0 版把设备连接到 Conol 桌面应用中的对话。在手持设备上打开一个聊天、阅读最近的消息、口述一条后续消息，或回答一个提问。同样的本地配套程序接口也开放给其他应用。

你的 Conol 对话，集中在一起

兼容的 Conol 桌面应用运行并登录后，聊天会出现在 Conol 下，带有它的机器人马赛克图案和一个 + New chat 启动器。选择一个对话，即可查看最近公开的用户和助手消息。按住 PTT 口述一条后续消息，或对着启动器口述来新建聊天。

新建的聊天会在设备上打开，等着你的下一条消息。Conol 会自动发现本地的 OpenWalkieTalkie 服务；没有需要配置的终端钩子或单独的模型 API 密钥。这个连接需要带有 OpenWalkieTalkie 桥接的 Conol 桌面应用；浏览器版不会连接本地服务。

在手持设备上回答整份表单

Conol 可以把 AskUser 表单和工作流批准一次一个问题地呈现出来。翻看单选题、切换多选、口述自由文本回答，然后先检查和修改，再明确提交整份表单。配套程序的套接字重新连接后，草稿回答仍会保留。无法用这种方式完成的表单会在 Conol 中打开。

会话面板显示对话实际使用的模型和思考强度。对 Conol 来说，这些目前是只读的；请在 Conol 中更改。对话记录同步公开的用户和助手文字。图片、工具输出和私有的推理过程留在所属的应用中。

对其他应用开放

这个集成使用公开的 JSON-RPC 接口。应用可以通过 agent.companion.set 提供自己的分组和新建聊天启动器，发布消息和提问，并通过 agent.session.set 报告实际的模型和思考强度。支持可编辑设置的应用，会按确切的修订号确认每一次请求的更改。

新的原生配套程序指南介绍了发现、注册、对话记录、表单、设置和重新连接。试试独立的 Python 示例：它使用脚本化的回复，不需要模型 API 密钥，没有安装 Conol 也能运行。自动生成的 API 参考记录了请求模式和权限。

让新聊天保持焦点

服务现在会在聚焦之前，先告知被替换槽位的新占用者。设备会在松开 PTT 后立即跟随配套程序的明确选择；有输入正被按住时会等待；如果你导航到别处，它会让步。未完成的提问保持打开。

八个共享槽位的上限不变。打开一个溢出的配套程序聊天，可以替换同一连接、同一应用和同一账户下一个未固定的同级聊天，同时保留启动器和其他账户正在忙的聊天。

更新到 0.11.0

安装已签名并经过公证的 Mac 应用（Apple Silicon 或 Intel），或选择检查更新。需要 macOS 13 或更高版本。通过 USB-C 连接设备，然后选择服务 → 更新 → 检查固件更新。原生配套程序支持需要 Mac 上的服务和固件都是 0.11.0。如果旧的服务还在运行，请选择服务 → 重新启动。另外请把 Conol 更新到带有 OpenWalkieTalkie 桥接的版本。

普通更新会保留设置和蓝牙配对。恢复协议 2 和闪存布局不变。单独的出厂 ZIP 用于生产，会覆盖设置和配对。

自动化测试覆盖了所有权、分组、槽位提升、设置确认、焦点顺序、按住的输入、协议解析、渲染，以及示例中的表单和重新连接。本版本没有重复进行实际的 Conol 对话测试和主板测试。
