连接 Codex

CLI、Codex Desktop 与一个本地 daemon · 约十分钟

有两条路，而且它们不一样。Codex CLI 自己就能接到设备上；Codex Desktop 需要一个启动器，把它放到同一个本地 daemon 上。

连接的是什么

应用不安装 Codex，也不代理它。它对话的是 Codex 跑的那个本地 daemon，所以设备上显示的就是那个 daemon 手里的会话。

  • Codex CLI —— 共享 daemon。不用写文件，也没有安装器；那一行就是个开关。
  • Codex Desktop —— ~/Applications 里的一个启动器，负责拉起或复用那个 daemon，并把 Desktop 指到它的 Unix socket 上。 这个启动器仅适用于 macOS。
  • hooks 兜底 —— 只在 daemon 这条路走不通时才用：往 $CODEX_HOME 里写一份 hooks.json。

1 · Codex CLI

  1. 照平常的方式，在你想要的项目里开会话：codex。
  2. 会话运行后，Codex CLI 那一行会自动开启，显示会话数，设备上也会出现条目。在 Omarchy 上，安装后这一行显示“关闭”，因为安装脚本设定了 codex.daemon=false，由 Omarchy 桥接登记这些会话。

2 · Codex Desktop

  1. 在 Codex Desktop 那一行按 设置。它会把 Codex with OpenWalkieTalkie.app 写进 ~/Applications。
  2. 把 Codex Desktop 和 ChatGPT 彻底退出。启动器不会打断已经在跑的会话。
  3. Finder → 前往 → 前往文件夹… → ~/Applications → 打开 Codex with OpenWalkieTalkie.app。

启动器会拉起或复用本地 daemon，并通过它的 Unix socket 把 Desktop 接上。以后每次都从这个启动器打开 Desktop：从正常图标打开，它就回到自己的 daemon，设备上就读不到东西了。

3 · 应该看到什么

  • Codex CLI 行：daemon 能连上时显示已连接；CLI 和 Desktop 的线程共用这个计数。
  • Codex Desktop 行：已安装 只说明启动器文件就位了。
  • 设备上：CANCEL → Agents，Desktop 的线程就排在 CLI 会话旁边。

出问题的时候

Codex 没在运行
这一行需要一个活着的 daemon。开一个本地 codex 会话，或从启动器启动 Desktop。
启动器不让启动
Quit Codex Desktop / ChatGPT first, then open Codex with OpenWalkieTalkie again. Running sessions are not interrupted automatically. 把两个都退掉，再开一次启动器。
显示已安装，但设备上什么都没有
已安装 说的是文件。Desktop 必须从启动器起，设备才看得到。
hooks 兜底不响了
hook 的信任是按位置、按 hooks.json 的真实路径算的。文件或路径一变，Codex 就把它当成 modified，然后静默失效：回到应用里重新授予信任。

这一页是怎么核对的

标签和路径取自应用与 0.17.0 的后台服务源码，启动器自己那句提示也是原文。两条路都没有在这个构建上端到端跑过：写这一页时，没有任何 CLI 线程或 Desktop 线程真的上过设备。
