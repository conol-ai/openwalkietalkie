连接 Grok Bot

一个 routine、一个 webhook、一把 key · 约十分钟

Grok Bot 跟前两个反着来：没有本地会话可以挂。你在 Grok Bot 里建一个 routine，把它指向这台机器，设备就成了那个机器人的麦克风和屏幕。

连接的是什么

一个机器人 = 应用配置文件里的一行 + 系统替它保管的一把 key。webhook 在 Grok Bot 那边；应用只负责发过去、读回来。

  • 机器人 —— config.toml 里的一条 [grokbot.bots.<id>]：名字、webhook 地址和设置。
  • key —— 由系统保管，不在那个文件里：macOS 进钥匙串（service ai.cohdl.openwalkietalkie，account grokbot.bots.<id>.key），Windows 进凭据管理器，Linux 或隔离的数据目录才落到 grokbot-keys.toml。
  • routine —— 在 Grok Bot 里建，不在这里。地址和 key 都是它给的。

1 · 在 Grok Bot 里建 routine

  1. 在 Grok Bot 里打开你要的那个机器人，进 Settings → Computer，允许它执行命令：不允许的话，routine 能回话，但什么都做不了。
  2. 建一个 routine，然后在聊天顶部点机器人的名字 → Details → routine → Webhook。那里会给出一个 POST to 地址和一个 key。

2 · 在这里添加机器人

  1. 打开 集成 → Grok Bot → 机器人… → 添加。
  2. 起一个你希望显示在设备上的名字，粘贴 POST to 地址和 key，按 添加。
  3. 按 测试：它会给 webhook 发一个请求，并告诉你 routine 有没有接受。

如果那一行给了 复制提示词，那段话是用 Grok Bot 自己的说法描述同一个 routine：发到机器人的聊天里，Grok Bot 会替你把 routine 建好。两种做法最后都是拿到一个地址和一把 key。

3 · 应该看到什么

  • Grok Bot 行：已设置，带机器人数量；第一个加进来之前是 未设置。
  • 缺少密钥 表示配置里有这个机器人，但系统里没有它的 key：拿 routine 当前的 key 再加一次。
  • 设备上：CANCEL → Agents 会按名字列出这个机器人，哪里都不用开着聊天。

出问题的时候

Grok Bot 拒绝了密钥（HTTP 401）
routine 重建过，或者 key 轮换了。重新复制 routine 的 key，再加一次机器人。HTTP 403 也是同一个处理。
Grok Bot 不认识这个 Webhook（HTTP 404）
这个地址指向的 routine 已经不存在了。重新复制 routine 的 POST to 地址，再加一次机器人。
缺少密钥
配置里有这个机器人，系统里没有它的 key。再加一次：同一个机器人重复添加会沿用原来的 key，除非你给了新的。
机器人会回话，但用不了电脑
Grok Bot 的 Settings → Computer 没允许。routine 照旧跑，设备照旧显示出字，但什么都不会执行。
Grok Bot 没有开始运行
key 被接受了，但这一次运行没有起来。暂停中的 routine 就是这样——应用会问 「例行任务是否已暂停？」——所以去 Grok Bot 里恢复它，回来再按 测试。

这一页是怎么核对的

各行状态和报错原文取自应用与 0.17.0 的服务源码，存放位置取自服务自己的文档。这一页没有对着真实 Grok Bot routine 跑过：上面那些 HTTP 回答是应用自己的字符串，不是对活 routine 的观察。
