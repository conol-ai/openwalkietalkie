教程 · CLAUDE CODE · 应用 0.17.0

连接 Claude Code

插件、Channels 与一个活会话 · 约十分钟

设备对话的是你机器上已经在跑的 Claude Code 会话。两件事必须成立：插件装进了 Claude Code，会话是用 Channels 启动的。

连接的是什么

应用里的「设置」并不安装 Claude Code。它写一份本地插件市场目录到 ~/Library/Application Support/OpenWalkieTalkie/claude-marketplace/ 并把它登记进去，让这台机器的 Claude Code 知道设备的存在。

  • 插件：一组 hook，让会话能把自己报告给后台服务。
  • Channels：应用读取的实时通道，会话就是靠它出现在设备上。单独一行，单独开关。
  • 你的项目：不动。插件装在用户级，不按项目装。

Linux

在 Linux 上，Omarchy 桥接会把你的 Claude Code 会话送到设备上。Claude Code Channels 是双向消息通道，本版本暂不可用，下个版本会修复。在此之前，下列步骤适用于 macOS 和 Windows。

1 · 安装插件

  1. 打开 集成，找到 Claude Code。如果那一行写着 设置，按它。
  2. 如果那一行给了 复制命令，把下面两条命令在终端里跑一遍。两条都可以重复执行。
  3. 插件装好之前就已经开着的会话，看不到它。新开一个，或在里面执行 /reload-plugins。
claude plugin marketplace add '<marketplace path>' --scope user --json
claude plugin install openwalkietalkie@openwalkietalkie --scope user --json

插件在用户级登记好之后，那一行会显示 已连接。这句话说的是文件，不是正在跑的会话。

2 · 带 Channels 启动会话

Claude Code 不会自动加载 Channels，除非你在启动时点名要它。

claude --dangerously-load-development-channels plugin:openwalkietalkie@openwalkietalkie

应用里这条命令在 集成 → Claude Channels → 如何连接… → 复制命令 后面，路径一样。首次启动 Claude 会要求确认：允许即可。

3 · 应该看到什么

  • Claude Code 行：已连接；会话开起来后，还会带一个会话数。
  • Claude Channels 行：自己的状态，Channels 会话没跑起来之前是没有会话连接。
  • 设备上：按 CANCEL 进入 Agents，会话就列在那里。设备上不需要再配置别的。

出问题的时候

需要修复
刚升级应用时，显示需要修复是正常的。受管的插件文件与 Claude Code 的记录不再一致。按一次修复，应用就会重写插件并重新登记。
Claude Channels 上没有会话连接
会话不是用 Channels 参数起的，或者确认被取消了。退掉重开，用复制来的那条命令。
显示已连接，但设备上没有条目
仓库自己的 .claude/settings.json 可以用 enabledPlugins["openwalkietalkie@openwalkietalkie"]: false 把这个仓库的插件关掉。应用看不到这个开关。
更新之后就不灵了
插件是在会话启动时读的。更新前就开着的会话，需要 /reload-plugins 或重启。

这一页是怎么核对的

所有标签和路径都取自应用本身与 0.17.0 的后台服务源码，两条命令就是应用复制给你的那两条。这一页没有用活的 Claude Code 会话端到端跑过，所以请把顺序当作代码假设的顺序，而不是一次实跑的记录。
