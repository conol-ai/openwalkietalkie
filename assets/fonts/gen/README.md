# Generated glyph atlases

`<font>.bin` are the 4 bpp glyph atlases of the deck type ramp, one per
`theme::Font`, with their metrics in `src/ui/font_data.rs`. Both are written by
`tools/generate-ui-fonts.py` from the vendored Noto Sans static TTFs in the
parent directory (`NotoSans-{Regular,SemiBold,Bold}.ttf`, SIL Open Font License
1.1, see `../OFL.txt`; Noto Sans 2.x from fonts.google.com). The generator's
`RAMP` table is the one size table; `theme::RAMP` must agree with it.

Regenerate after changing the ramp, the coverage or the TTFs:

    tools/generate-ui-fonts.py            # rewrites gen/*.bin and src/ui/font_data.rs
    tools/generate-ui-fonts.py --check    # regenerates to a temp dir and diffs

Needs Pillow (FreeType rendering, hinted, at the em size) and fontTools (to
read the cmap). Output depends on the installed FreeType version; commit the
regenerated files together with the change that needed them.

The rich message faces add RowStrong (25 px), TextStrong (29 px), Reading
(32 px regular), and Code (25 px Noto Sans Mono). The variable
`../NotoSansMono.ttf` is rasterized at regular weight and normal width; its
license is `../NotoSansMono-OFL.txt`. Missing glyphs fall back to Noto Sans
before the deck’s drawn symbols.

Coverage: ASCII, Latin-1 Supplement, Latin Extended-A, – — ‘ ’ “ ” • … ‹ › and
the symbols ← ↑ → ↓ ↵ ⏎ ✓ and the Mac modifiers ⌃ ⌥ ⇧ ⌘, plus U+FFFD. Noto
Sans has no arrows, check mark, return or modifier symbols, so those eleven are
drawn by the generator from lines in the weight's stroke width (`drawn_shape`). U+FFFD is drawn as a hollow box and is
what every codepoint outside both the Latin and CJK tables renders as.

## Chinese and Japanese fallback

`cjk.bin` and `cjk-metrics.bin` are generated by
`python3 tools/generate-cjk-font.py` (`--check` verifies them). They share one
regular-weight, 26 px bitmap across every face; the firmware uses bilinear
filtering when scaling. Four coverage levels per source pixel keep 28,759
glyphs within a 5.2 MB budget, without a runtime font engine or allocations.
The bitmap uses 4,840,990 bytes and its metrics use 345,108 bytes, for
5,186,098 bytes total. Japanese kana add 268 glyphs and 30,881 bytes to the
original Chinese atlas.
The Latin atlases remain unchanged. The host mounts the same lookup and
scaling code, so its line widths agree with the device.
The CJK atlas and metrics use the upper NOR bank starting at `0x12720000`
through `flash-assets.x`, leaving the lower bank available for code and other
constants. On every board the code and atlases stay in NOR flash; no font data is copied
into PSRAM at startup. The corrected clock configuration supersedes the old
Rev A/B PSRAM workaround. PSRAM is available for runtime buffers, with its
final MiB reserved for bench diagnostics (`memory.x` / `psram.x`).

Source: [Noto Sans CJK SC Regular, release Sans2.004](https://github.com/notofonts/noto-cjk/blob/Sans2.004/Sans/OTF/SimplifiedChinese/NotoSansCJKsc-Regular.otf),
vendored as `../NotoSansCJKsc-Regular.otf`. SHA-256:
`2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b`.
SIL Open Font License 1.1: `../NotoSansCJK-OFL.txt` (upstream release's
`LICENSE`). Simplified and traditional Chinese and Japanese kanji use the
source's Simplified Chinese regional glyph forms; this atlas does not select
different regional forms per language. Japanese kana come from that same
vendored source, so no additional font or license is required.

Coverage is the source cmap intersected with radicals U+2E80–2FDF, punctuation
U+3000–303F, hiragana U+3040–309F, katakana U+30A0–30FF and phonetic
extensions U+31F0–31FF, Bopomofo U+3100–312F / U+31A0–31BF, Extension A U+3400–4DBF,
unified ideographs U+4E00–9FFF, compatibility ideographs U+F900–FAFF and
fullwidth forms U+FF01–FF60 / U+FFE0–FFE6 plus halfwidth katakana and
punctuation U+FF61–FF9F. Combining and spacing kana voicing marks are included;
unassigned codepoints still have no glyph. Supplementary-plane ideographs
(Extension B onward), emoji and unrelated scripts still use the replacement
box. Two-em vertical repeat marks are reduced to fit a single line.

Bitmap rows contain `(w + 3) / 4` bytes, four 2-bit alpha values per byte,
most significant first (0 transparent, 3 opaque). Sorted 12-byte metric
records store little-endian `u16 codepoint`, `u8 advance`, `i8 left`, `i8 top`,
`u8 width`, `u8 height`, one reserved byte, and `u32 bitmap_offset`.
